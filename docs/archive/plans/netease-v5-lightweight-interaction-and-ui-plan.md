## 1. 推荐方向与交付范围

建议把现有播放器从“多个功能面板加操作按钮”调整为“浏览内容 + 固定播放控制 + 按需展开的队列与歌词”。主要视觉投入放在文字、间距、颜色、矢量图标和当前状态；封面只在能帮助辨认内容的位置使用。

最终应形成以下体验：

1. 进入后能立即搜索、打开歌单或继续上次播放，当前页面和当前歌曲始终清楚。
2. 歌曲就地播放、加入队列；不必先选中，再到列表外寻找操作按钮。
3. 浏览、排队、看歌词之间切换时保留上下文，播放控制不移动。
4. 深浅主题有一致的视觉语言；重点突出，信息量适合桌面和 Dock 小面板。
5. 不新增装饰图片包、背景视频、持续频谱或 WebView。隐藏界面时停止新增的视觉工作。

本期针对现有登录、搜索、只读歌单、队列、定位、歌词、本机历史、恢复及设置做体验改造。喜欢/收藏写入、推荐、歌手/专辑详情、下载管理、桌面歌词和系统媒体键继续属于[能力路线图](../../roadmap/netease-capability-roadmap.md)的后续范围。界面不摆放尚不可用的爱心、下载、音质切换或“发现”入口。

**推荐交付到第 10 节的阶段 D。** 封面取色、歌词平滑居中和队列拖拽作为增强项单列；核心体验不依赖它们。

阅读建议：产品决策看第 2–5 节，视觉和资源取舍看第 6–8 节，开发落地看第 9–11 节。详细测试范围单列为 [V5 专用验证计划](../../maintenance/netease-v5-ui-interaction-verification-plan.md)，实际自动验证与实机边界单独记录。

## 4. 页面结构与自适应布局

### 4.1 页面分层

- 浏览导航固定为 **搜索 / 我的歌单 / 最近播放**。三个入口使用有选中态的轻量 Tab，不再做五个同形按钮。
- 搜索框放顶栏，Enter 提交并进入搜索页。首次登录默认搜索；同一 Document 内返回时保留原导航和列表状态。
- 底部播放条始终可用：当前曲目、上一首、播放/暂停、下一首、进度、模式、音量、歌词、队列。
- 点击歌词进入 Document 内容区内的“正在播放”视图；点击返回恢复原浏览页。它不创建第二播放器或独立顶层窗口。
- 队列在宽屏展开为右侧面板；中窄屏切换主内容区，保留底部播放器和明确返回按钮。宽屏默认关闭，不挤占第一次使用的内容区。
- 设置继续使用现有 Tool；从账号菜单增加明确入口，接入时核对公开 SDK 的 Tool 打开方式。

### 4.2 宽度与高度规则

这里的宽度是插件实际获得的内容宽度，单位 DIP，不是显示器物理像素或 Host 窗口宽度。

| 内容区域 | 浏览与队列 | 播放条 | 歌词视图 |
| --- | --- | --- | --- |
| ≥1120 宽，且高 ≥600 | 顶部三项导航；队列可在右侧占 300–320；主内容至少约 720 | 目标 88–96 高；曲目、主控制、辅助入口分组，进度独立细行 | 可用 200–240 封面 + 歌词；打开队列后按剩余宽度退为单列 |
| 800–1119 宽 | 三项导航；队列占主内容；歌曲表按剩余宽度决定专辑列 | 目标 88–104 高；辅助入口保持紧凑 | 以歌词为主；封面只在空间充足时显示 |
| 520–799 宽 | 搜索框独占顶栏主要空间；紧凑导航；歌曲/歌手两行 | 目标 96–112 高；音量放弹出层；上一首/播放/下一首始终直接可达 | 只显示曲目信息和歌词，取消大封面 |
| 高度 420–599 | 歌单详情头部压到 ≤72；缩小非必要留白；列表仍独立滚动 | 不因附加状态再挤出多排常驻文字；错误可展开 | 单列歌词，工具条 ≤36；至少能辨认当前句及邻近句 |

V5 正式验收下限继续为 **520×420**；低于下限只提供合理降级，不宣称全部操作已覆盖。设置 Tool 继续覆盖 280/320/420×900 与 640×240，底部低矮 Tool 内部可纵向滚动。

歌曲列的断点以**列表实际宽度**计算，不能直接沿用整个 MusicView 的宽度；否则右侧队列打开后会挤坏表格。宽窄切换只改变布局和呈现位置，不更换播放会话、重复加载页面或启动两个队列视图。

## 5. 逐功能交互方案

### 5.1 登录与账号

- 保持微信默认、网易云 App 备用；用两项方式切换明确当前渠道。二维码仍有固定白底和静区。
- 初始只突出“生成二维码”；等待扫码时显示“请用微信扫码”或“请用网易云 App 扫码”；扫码后变为“请在手机确认”，避免只显示含糊的“处理中”。
- 过期显示“二维码已过期”和“刷新二维码”；不靠倒计时驱动持续重绘。失败保留错误原因和就近重试。
- 已有本地会话时先明确“正在恢复登录”；恢复失败再提供扫码，不同时把所有登录按钮作为主动作。
- 头像菜单包含账号信息、设置、恢复/重试（仅适用时）、退出。退出旁说明会停止播放并清理本机账号状态。
- 本地保存失败属于持续状态，放账号提示条和设置内；不只给几秒即消失的 Toast。

### 5.2 搜索与通用歌曲行

**输入：** Enter 或搜索按钮提交；输入中文组合过程中 Enter 不触发。V5 默认不做边输入边请求，不增加建议接口。新请求取消过时请求，只接纳最新关键词/页面/账号对应结果；加载时保留可理解的已有内容并显示局部状态。

**结果：** 搜索、歌单曲目、历史和队列共用视觉规则，但各自保留数据与命令语义。歌曲行包括序号/播放标记、名称、歌手、按空间显示的专辑、时长，以及保留固定宽度的操作区。

| 操作 | 建议结果 | 可发现性 |
| --- | --- | --- |
| 单击歌曲行 | 仅选中，不出声 | 轻选中底色，不冒用播放标记 |
| 双击、Enter 或行内播放 | 执行该来源的默认播放动作，见下一节 | 悬停/焦点/选中时显露播放；右侧更多一直可见；触屏不依赖 hover |
| 更多 / 右键 / Shift+F10 | 下一首播放、加入队列；队列内另有移除/移动 | 相同命令对象，避免三种入口规则不同 |
| 加入队列 | 尾部追加，当前播放不变 | 短提示“已加入队列 · 1 首”，队列数量立即更新 |
| 下一首播放 | 按现有优先规则排队，当前歌曲不打断 | 提示“将在当前歌曲后播放”；空队列仍保持待播 |

不新增自动换页或无限滚动。保留服务器分页、页数/数量及加载更多；搜索页翻页按钮位置固定，加载状态不让表格上下跳动。搜索无结果显示关键词和“修改关键词”动作；网络失败显示重试，与无结果区分。

### 5.3 必须明确的播放语义变化

**建议 V5 将搜索/历史中的“立即播放”改为保留原队列。** 当前 V4 的搜索和历史播放会调用单曲播放并替换成单项队列；这容易在临时试听后丢失原来的待播内容。此项属于本地播放交互的行为变更，需要独立实现和验证，不能只替换按钮文案。

| 来源/动作 | V5 推荐规则 |
| --- | --- |
| 搜索/历史：立即播放 | 有队列时，把新条目放在当前项之后并切到该条目；原有条目保留相对顺序。无队列则建立单项队列并播放。命中正在播放的同一曲目时继续当前项，不新增重复项 |
| 歌单曲目：双击/Enter/行内播放 | 默认也是单曲立即播放，保留原队列；避免“同一播放图标在不同页面偷偷换整单” |
| 歌单：播放全部 | 用该歌单完整、有序的 ID 快照替换队列，从头播放；按钮说明“替换当前队列”。不完整快照禁用并给原因 |
| 歌单：从这里播放 | 明确放在行菜单中；按完整歌单快照替换队列，从该位置开始。当前 50 行仅为浏览分页 |
| 队列：播放此项 | 按 EntryId 选择现有位置，不复制条目；作为明确的播放意图，暂停/停止时也开始播放 |
| 上一首/下一首 | 延续 V4：暂停/停止时只改变待播项；正在播放时换曲继续。与“播放此项”区分 |
| 加入队列/下一首播放 | 延续 V4；空队列只建立待播，不自动出声 |

立即播放是明确出声的意图，必须在共享协调器内一次性处理插入、选中和启动，不能由 View 连续调用 Enqueue/Select/Pause 拼接，避免多 Document 并发穿插。同曲在队列其他位置时不按 TrackId 任意跳转或删除，仍可生成独立 EntryId。

失败后显示实际选中项和失败原因，保留队列并可重试/切下一首；不在界面上假装已经播放。随机、单曲循环、下一首优先以及内容不可用的有限推进继续遵守现有规则。实现阶段需单独覆盖“立即播放失败后接下来播什么”的集成用例。

### 5.4 我的歌单与详情

- 默认使用有界的纵向歌单列表；每项为 40 DIP 小封面或矢量占位、歌单名、自建/收藏、歌曲数。模型已有 Cover，可按可见项加载。
- 名称作为可聚焦入口，单击/Enter 直接打开；不再先选中再按“打开所选”。暂不增加批量选择歌单需求。
- “全部 / 自建 / 收藏”可做本地视图筛选；明确仅筛选**已加载的歌单**。需要更多时继续既有分页，不能把当前页无匹配误报为账号无歌单。
- 详情顶部只保留返回、歌单名称、数量、主操作“播放全部”和更多；封面 64–80 DIP，窄/矮布局收为 40 或省略。
- 返回保留已加载列表、筛选条件、滚动和选择；正在播放时刷新歌单只刷新浏览数据。
- 描述、缺失资料和“不完整列表”按需展开；不完整状态必须持续可见，不能藏到工具提示里。
- V5 不做多列封面墙。将来若加入卡片模式，必须先解决网格虚拟化和图片预算，不能直接换为无界 WrapPanel。

### 5.5 播放条、进度和音量

- 上一首/下一首使用 18–20 DIP 矢量图标，主播放按钮 36–40 DIP；每个可点击区域至少 32×32，常用主按钮至少 40×40。配工具提示、键盘焦点和自动化名称。
- 播放与暂停共享一个位置；缓冲时该位置显示有限加载状态，取消/停止仍可从更多直接取得。不会因状态变化让其他控件横向跳动。
- “停止”放更多菜单，说明“停止并回到开头”；保留暂停与停止的不同含义。
- 播放模式有常驻图标和菜单，菜单显示四种名称与当前勾选项；不要求用户猜图标并反复点击循环。
- 时间与进度稳定显示；拖动预览时间就近出现在滑块提示中，松手/松键提交一次。失败显示真实位置；未知时长、不可定位或试听范围受限时给具体原因。
- 完整缓冲期间显示真实字节/已知总长，不模拟“秒开”和虚假缓冲百分比。UI 优化不能消除当前“完整下载后才打开音频”的等待。
- 音量宽屏可直接调整，窄屏用按钮打开小弹层；新增静音应记忆最后非零音量，恢复后使用该值。无数值变化时不发重复音量命令。
- 封面或歌词按钮进入正在播放页；队列按钮携带条目数。过长名称截断，完整标题可通过提示/详情查看，不做永久跑马灯。

### 5.6 队列

- 宽屏侧面板、窄屏内容页复用一份页面投影；不要同时挂载两个隐藏的大列表。
- 当前项用静态播放图标 + 明确文字/字重标识；选中另一项时当前播放标记仍保留。无需持续跳动的均衡器图标。
- 显示“当前 / 接下来”和来源；随机模式不得把普通列表顺序冒充实际随机下一首顺序。若没有精确排程快照，使用“队列顺序”并标明当前随机模式。
- “定位当前”滚到当前项；打开时仅首次定位，不在用户滚动整理时持续抢回位置。
- 移除放行菜单，移除当前项沿用 V4 的播放状态规则。短时撤销可作为增强项，但必须有版本/EntryId 校验，不能覆盖别的 Document 的后续操作。
- 清空放面板更多菜单；非空时在面板内确认“清空 N 首并停止播放”，可取消。它与移除单行有不同的误操作成本。
- 上移/下移继续保留菜单和键盘通道；拖拽仅列增强项。若实现跨多位置移动，要新增一次性 MoveTo 命令，不能逐格调用 Move 导致大量重建和保存。

### 5.7 歌词与正在播放

- 正常模式歌词 22–26 DIP，窄屏 18–22；翻译 13–15。整体以左对齐阅读列为主，限制最大行宽，长句换行不横向滚动。
- 当前句提高前景对比和字重；前后句降低视觉权重但保持可读。当前句不靠持续缩放表达，避免每次换行重新排版。
- 继续利用已有 LRC/YRC/翻译解析和真实媒体进度。逐字部分保持少量文本片段，不为每个字创建控件或计时器。
- 手动滚动、点击和键盘浏览暂停跟随；仅此时显示“回到当前句”浮动按钮。恢复跟随不重放此前动画。
- V5 核心先保证当前句进入可视区；平滑居中是增强项，只在换行时触发 120–180 ms 的一次性移动，支持虚拟化和减少动态效果；不以 60 Hz 驱动全列表。
- 增加“显示翻译”开关；仅在已有翻译时显示。歌词失败才出现重试；纯音乐、无歌词、纯文本和同步受限分别说明。
- 核心版本单击歌词只浏览；可选的“从这句播放”放显式行菜单，并复用 CanSeek 与真实时间映射。试听映射不明时禁止这一动作。
- 封面采用静态正方形，无唱片旋转、实时模糊或粒子。即使关闭全部封面，歌词页仍须依靠排版成立。

### 5.8 最近播放与恢复

- 明确标题“本机最近播放”，避免暗示网易全端记录。依据已有 PlayedAt 按本地时间显示“今天 / 昨天 / 更早”；这仍是歌曲最近播放列表，不变成每次播放事件明细。
- 复用歌曲行和立即播放/追加规则；不因历史页出现就再次记入历史。
- 恢复成功后显示一条可收起提示：“已恢复 128 首，停在 01:24 · 继续播放”。默认暂停，仅用户点继续才取资源并出声。
- 继续后权限、媒体长度或试听范围变化导致回到开头时，显示实际结果，不展示虚假的恢复成功。
- 关闭 Document 继续播放、退出账号停止等 V4 规则保持清楚；新导航不会改变插件与页面的资源寿命。

### 5.9 设置 Tool 与键盘

设置分为账号、播放组件、界面三组。播放组件正常时用一行摘要，异常时展开检测、目录与实际加载信息；草稿/保存值/实际值仍区分，保存不意味着运行库热切换。提供减少动态效果、封面开关，密度选择可随阶段 C 加入。

| 键盘操作 | 范围与规则 |
| --- | --- |
| Tab / Shift+Tab | 按可见布局顺序移动；图标按钮均有可见焦点 |
| Enter | 搜索框提交；歌曲行播放；歌单名称打开；控件内遵守自身语义 |
| Space | 仅在 Document 非文本/非交互控件的播放命令上下文切换播放；按钮、列表选择、Slider 等已消费事件不再次处理 |
| Shift+F10 | 当前行上下文菜单 |
| Esc | 先关当前菜单/弹层，再退出队列或歌词内容页；不退出登录，不停止音乐 |
| Ctrl+F（候选） | 活动音乐 Document 中聚焦搜索；实现前核对 Host 快捷键，冲突时保留按钮并换用可配置入口 |

本期仅接入 Document 局部键盘处理。Workbench Command、全局快捷键、媒体键属于后续宿主集成，不混入 V5 的完成标准。

## 6. 视觉规范：少量元素形成一致观感

### 6.1 设计基调

采用中性底色、清楚文字和小面积红色强调。最多三个背景层：页面、内容/播放条、弹层；列表以留白和选中背景分隔，减少“边框里再套卡片”。红色主要用于播放主按钮、选中导航、当前歌词和少量关键状态。

| 项目 | 建议规范 |
| --- | --- |
| 字体 | 系统已有字体及中文回退，不分发自定义字体包 |
| 字号 | 正文 13–14；辅助 12；页面标题 20–24；歌词见上节；避免满屏同一字号 |
| 字重 | 常规 / Medium / Semibold 三档；不用全列表加粗 |
| 间距 | 4/8/12/16/24 DIP；宽屏主体外边距 20–24，窄屏 12 |
| 行高 | 标准曲目行 44，窄屏两行 56；可选紧凑 36/48；实际以中文/DPI 验证为准 |
| 圆角 | 控件 6，面板 8，封面 6；主播放按钮可圆形；避免所有元素胶囊化 |
| 图标 | 统一 20×20 逻辑画布，16/20/24 档；单色几何复用，非彩色 Emoji；入口图标改为音乐语义 |
| 分隔 | 1 DIP 低对比边界；用背景层级表达大分区，正常按钮可无描边 |
| 阴影 | 只在菜单等悬浮层有必要时使用一次浅阴影；列表项和播放条不堆阴影 |

### 6.2 建议色板与状态

以下为设计起点，实施时检查最终背景上的对比度；颜色集中写入 `NeteaseThemeResources`，使用 DynamicResource，继承所在窗口深浅主题。

| 语义 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 页面 | `#F7F8FA` | `#17191D` | 大面积背景 |
| 内容面 | `#FFFFFF` | `#202329` | 列表/播放条 |
| 悬停面 | `#EEF0F3` | `#2A2E35` | 行和次级按钮 |
| 主文字 | `#20232A` | `#F2F3F5` | 歌名、主标签 |
| 次文字 | `#626875` | `#AEB5C2` | 歌手、时长、辅助说明 |
| 强调文字/图标 | `#C92B42` | `#FF7185` | 选中与当前播放 |
| 主按钮填充 / 文字 | `#C92B42` / 白 | `#FF7185` / `#17191D` | 深色主题不用白字压在浅粉底上 |
| 选中面 | `#FBECEF` | `#3C252D` | 浏览选择；不等同正在播放 |
| 边界 | `#E0E3E8` | `#373C45` | 分隔与弹层 |

普通文字目标对比度 ≥4.5:1；大号文字按对应条件 ≥3:1，参考 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。项目验收另要求可操作图标、焦点环对相邻背景尽量达到 3:1。错误/成功同时有文字和形状提示，不只变红/变绿。

所有按钮至少区分 normal、hover、pressed、focus、disabled；异步动作再加 busy 和结果状态。禁用的原因在相邻说明或键盘可访问的信息中出现，不能只靠鼠标悬停到禁用控件。

### 6.3 轻量动效

| 场景 | 建议 | 限制 |
| --- | --- | --- |
| 悬停/按下 | 背景色 80–120 ms；按下颜色更明确 | 不改变控件尺寸，不移动命中区域 |
| 导航/内容状态切换 | 内容一次淡入 120–160 ms | 不为每一行做入场，不保留多份旧页面做交叉淡化 |
| 队列开关 | 可选 160 ms 内淡入/≤12 DIP 位移 | 列宽一次切换；不逐帧动画 Width/Height/Margin |
| 歌词换行 | 核心为前景/字重状态切换；平滑滚动后置 | 只处理当前/前一行，不能重建全列表 |
| 加入队列反馈 | 固定位置短提示约 2–3 秒 | 无重复计时器堆积，重要失败不自动消失 |
| 加载 | 仅在实际忙碌且可见时显示局部指示 | 减少动态效果开启时保留静态状态文字 |

沿用 [ViewMotion](../../../src/MusicNetEasePlugin.Plugin/Infrastructure/Ui/ViewMotion.cs) 的偏好、主题切换和可见性控制。隐藏、最小化、脱离视觉树、减少动态效果时撤销新增动画；重新显示只投影最新状态。不开启旋转封面、频谱、呼吸灯、闪动 skeleton 或动态背景。

## 7. 资源预算与 Avalonia 实现约束

### 7.1 预算先于效果

下列是 V5 的建议验收目标，需阶段 A 建立同机 V4 基线后验证；不是已经测得的性能结果。预算按插件容器汇总，不能每开一个 Document 就重新获得一份完整预算。

| 项目 | 建议预算/约束 | 不达标时处理 |
| --- | --- | --- |
| 新增内置装饰位图、视频、字体 | 0；仅小量矢量路径与样式 | 使用几何占位、系统字体 |
| 新增矢量/主题静态资产 | 未压缩合计目标 ≤100 KiB | 精简图标集合；不带整套第三方图标包 |
| 分发体积 | 开发期记录同配置构建目录的文件/字节增量；未来发布 ZIP 增量目标 ≤300 KiB，不新增 UI/渲染运行时依赖 | 本期不为测 ZIP 运行发布或打包门禁；正式发布时再核对同条件 ZIP，不能通过移除既有功能“达标” |
| 图片在途请求 | 全容器最多 2 个，当前曲目优先；相同键合并请求 | 取消不再需要的请求；失败使用占位 |
| 图片压缩字节缓存 | 全容器目标 ≤8 MiB，单响应继续 ≤2 MiB | LRU 淘汰，无默认磁盘封面缓存 |
| 解码图片 | 全容器目标 ≤16 MiB、≤24 个缓存条目；当前使用项计入预算 | 引用项不能强制释放；容量不足时减少预取/缩略图，以占位降级 |
| 图片尺寸 | 列表 40 DIP、播放条 44–48 DIP；请求/解码按 DPI 取必要档，最长边不超过 512 物理像素 | 先试现有 160 档；较大档需验证 CDN 和本地解码路径，不默认下载原图 |
| 内存增量 | 固定数据/视口/主题下，V5 相对 V4 稳态 Private Bytes 增量目标 ≤32 MiB | 分离托管堆、原生图片和音频缓存来源；优先关大封面与增强动效 |
| 空闲/隐藏视觉工作 | 新增装饰循环计时器 0；隐藏页不下载新装饰图、不刷新歌词布局 | 取消 View 订阅/任务；播放服务继续工作 |
| 进度投影 | 保持现有原生约 200 ms 节流；时间文字按显示值变化更新 | 不新增 60 Hz 插值时钟；seek/状态改变立即反馈 |
| 大列表 | 曲目 50/页、资料缓存 500、完整歌单 ID 10,000 等 V4 上限继续有效 | 可见容器数随视口而非总行数增长；禁止为所有行同时解码封面 |
| 热态本地交互 | 无网络动作的首个可见反馈目标 p95 ≤100 ms；结构切换目标 p95 ≤150 ms | 优先检查布局、列表重建及 UI 线程解码 |
| 流畅性观察 | 60 Hz 基准机上滚动帧耗时目标 p95 ≤20 ms；≥50 ms 停顿需定位 | 不把“开了 GPU”当作性能通过；若测量工具不可用则标为未测 |

例如 160×160 的四字节像素约占 100 KiB，512×512 约占 1 MiB，实际还可能有 GPU 副本和对象开销。压缩文件只有几十 KiB 不代表解码后同样小，因此缓存应同时按条数和解码字节预算，而不能只数图片文件。

### 7.2 图片与背景策略

1. **核心阶段：** 保留当前歌曲与头像，加入可见歌单小封面；搜索、队列、历史的每一行不铺封面。
2. **按需阶段：** 正在播放页展开且空间足够时，才申请中等尺寸封面。关闭后释放页面引用。
3. **可选增强：** 从小尺寸像素样本提取一次低饱和颜色，缓存到该图片版本；只用于很浅的静态背景色，文字对比仍走固定语义色。失败立即退回默认，不逐帧取色。
4. 图片缓存键包含账号作用域/epoch、规范化图片地址和尺寸档；同账号跨 Document 复用。退出后取消请求、清空缓存，迟到结果不得重新写回。
5. 图片服务只处理允许的网易图片地址，不携带登录 Cookie，保留超时和读取上限。较大图片需在**解码前/解码过程中**限制实际尺寸，不能仅给 Image 控件设 Width。
6. 如果做共享解码缓存，要有明确 lease/引用计数：View 释放引用，缓存到零引用后再 Dispose。不能让一个 Document Dispose 掉其他 Document 正在使用的 Bitmap；不得共享同一个 Image/Control 实例。
7. 多页面同时需要不同歌曲时，预算仍为全容器上限；允许显示占位，不通过悄悄扩容解决冲突。设置“显示封面”关闭后取消图片装饰请求，二维码不受此开关影响。

### 7.3 列表、事件与图形

继续用现有 `ListBox + VirtualizingStackPanel` 和有限高度的布局；不为纯展示曲目引入复杂表格/网页引擎。几何尽量一次解析、运行期复用，保持浅视觉树和编译绑定。此方向与 [Avalonia 官方性能指南](https://docs.avaloniaui.net/troubleshooting/app-performance-issues)中的虚拟化、简化布局、缩略图和几何复用建议一致；具体 API 必须以仓库使用的 Avalonia 12.1.2 核验。

源码中队列按 QueueRevision 重建投影，进度不复制全队列；V5 延续这一边界。新增行操作后，对移动、当前项切换优先按 EntryId 更新受影响行，避免一次小操作 Clear/Add 10,000 行。加载动画、进度、歌词不能顺带刷新全部导航和曲目信息。

底层播放和持久化订阅可以继续存在；停止的是隐藏 View 的绘制、滚动、封面请求和不必要的页面通知，不能因为页面不可见就暂停音乐或丢失恢复信息。

## 8. 反馈、错误与可访问性

| 情况 | 展示位置与动作 | 行为约束 |
| --- | --- | --- |
| 普通加载 | 当前内容区域小状态，保留布局 | 超过约 150 ms 再呈现辅助加载态，避免闪烁；这是可取消的一次延迟，不是循环动画时钟 |
| 空列表 | 图标 + 一句原因 + 一个下一步 | 搜索为空、无歌单、无历史、空队列使用不同文字；不用空白大面板 |
| 加入队列成功 | 播放条附近短提示 | 不弹阻断对话框，不每次跳到队列 |
| 播放失败 | 播放条内错误摘要，可展开详情；重试/下一首 | 不显示假播放态，不为网络错误不断自动换曲 |
| 内容不可用/试听 | 对应曲目或播放条的标记 | 只有接口事实可支持时才显示原因，不预判“VIP 可完整播放” |
| 歌词失败 | 歌词区域重试 | 不阻止音频和其他导航 |
| 会话失效 | 账号区域明确重新登录 | 保留可解释的失效原因，按现有规则清理个人状态 |
| 本地保存/清理失败 | 持续提示 + 就近重试 + 设置内详情 | 不用自动消失提示替代，不每条进度播报 |

所有隐藏式动作都必须有键盘/触摸等价入口。菜单打开后焦点进入菜单，关闭后回到触发控件；页面切换后焦点落在明确标题/首个操作，返回可恢复原焦点。LiveRegion 只播报状态变化和结果，不朗读每个时间 tick 或逐字歌词。

### 9.2 SOLID 是首要工程约束

这里按实际责任和契约检查 SOLID，不以类数量、接口数量或模式名称作为完成指标。

| 原则 | V5 的具体要求 | 代码审查检查点 |
| --- | --- | --- |
| S：单一职责 | View 负责布局、焦点和输入转发；导航状态只负责页面切换；播放条模型只投影共享播放状态；队列协调器处理播放意图；图片服务管理缓存和寿命 | XAML 后台不得复制队列算法、持久化或登录规则；MusicWorkspace 不继续累积导航、图片解码、播放、历史的所有责任 |

生命周期也属于职责边界：共享播放器归插件容器；浏览与焦点归 Document；可见图片引用归 View；偏好持久化归存储服务。组件关闭只释放自己拥有的资源，不越权停止共享音频或释放其他页面仍在使用的图片。

### 9.3 朴素设计模式与中文注释

- 沿用现有 MVVM、命令绑定、构造注入和事件订阅即可。按钮、Enter 和行菜单转发到同一命令，业务规则只有一份。
- 只有存在共享解码对象时才引入小型 lease；只有确有淘汰需求时才实现有界缓存。状态少时使用枚举和明确分支，不引入通用状态机框架。
- 不为这次 UI 改造增加事件总线、插件内插件系统、通用工作流或多层空壳工厂；不为了减少几行代码掩盖取消与释放逻辑。
- 新增或修改的责任边界、公开契约、并发/取消判断、预算退化和资源释放使用中文注释。说明“为什么这样设计、谁拥有资源、何时失效”，不逐行复述赋值代码。
- 测试使用清楚的准备/操作/断言结构；复杂时序用中文说明触发顺序与所保护的不变量。对改动的已有英文解释同步澄清，不批量改动无关源码。

## 11. 验收方法与通过标准

### 11.1 用户任务验收

| 场景 | 目标 |
| --- | --- |
| 搜索一首歌并播放 | 输入后 Enter，再双击/Enter/行内播放即可；无必须先到底部找按钮的步骤 |
| 不中断当前歌曲添加下一首 | 行菜单可完成；当前输出与进度不变；队列位置和提示准确 |
| 临时播放搜索结果后继续原列表 | 原有队列条目仍在；随机/顺序等模式行为符合定义，失败能解释 |
| 打开歌单并返回 | 名称一次激活进入；返回保持加载范围、筛选和滚动位置 |
| 播放全部/从这里播放 | 完整 ID 顺序正确；重复歌曲保留独立位置；不完整快照不冒充完整歌单 |
| 切模式/开歌词/看队列 | 不需要经过设置页；播放条持续可达；关闭恢复浏览上下文 |
| 拖进度与歌词手动浏览 | 定位只提交一次；暂停定位不出声；手动浏览不会被自动滚动抢回 |
| 重启恢复 | 显示可继续状态但不自动出声；用户点击后再获取资源和播放 |
| 520×420、中文长标题、200% DPI | 以可用 DIP 核验，核心控制可达，内容可滚动，文字/焦点/滑块不被裁剪 |
| 多 Document、Dock 重挂、最后一页关闭 | 一个共享播放器；关闭页继续播放；重开一致；退出账号停止并清理 |
| 减少动态效果/关闭封面 | 所有任务仍可完成，状态变化仍明确，无空白失效控制 |

### 11.2 资源验证

固定一台 Windows x64 机器，记录 CPU/GPU、内存、屏幕刷新率、DPI、Host/插件构建版本、主题、电源模式和原生音频后端。V4/V5 使用同一份合成歌单、同一音频文件/格式及相同账号场景；测试数据至少包括 1,000 歌单上限场景、10,000 队列 ID、50 行浏览页和长歌词。

按以下场景分别测量，每轮先预热，记录 3 次运行的中位值及尾部延迟：

1. 首次进入、热态导航、连续翻页/滚动、展开/收起队列。
2. 暂停空闲 60 秒、播放且歌词可见 60 秒、最小化/隐藏仍播放 60 秒。
3. 反复开关 Document/歌词/队列 20 轮、切主题 20 轮；检查订阅、计时器、请求和图片引用是否累积。
4. 2–3 个 Document 共享会话、快速切歌/账号退出，验证图片缓存去重和过期结果丢弃。
5. 网络失败、图片超限/损坏、歌词缺失、无运行库；验证降级路径不循环请求、不阻塞播放器界面。

报告至少包含：Private Bytes 稳态/峰值、托管分配趋势、CPU 时间增量、可见容器数、图片在途数/解码字节/命中情况、首次可见反馈耗时、布局/帧耗时（若可采集）。CPU 比较采用进程 CPU 时间 ÷ 墙钟时间，注明按单核 100% 计；空闲/隐藏场景目标 V5 较 V4 新增不超过 1 个百分点，并核验无新增视觉唤醒。音频 CPU 单列解释，不当作 UI 开销。

反复开关后看稳态是否持续增长，不能只用一次 GC 或短时工作集下降证明无泄漏。UI 帧耗时以实际采集工具为准；无法采集则写“未测”，不填估计数字。不存在跨客户端同机基准时，不写“比网易/某开源播放器省 X%”。

### 11.3 自动验证与视觉回归

- 命令级：立即播放的原子性、重复 EntryId、暂停/停止状态、并发页面、账号切换、替换队列、随机与下一首优先。
- 组件级：焦点/键盘/菜单动作不重复；图标可访问名称；布局断点；seek 草稿取消；不完整歌单禁用反馈。
- 资源级：缓存合并、取消、预算、引用计数；隐藏页无新增动画/图片工作；退出释放和迟到结果隔离。
- 截图：1200×720、800×600、520×420 的深浅主题；另核对真实 Host 的 Dock、浮窗、回停和 Tool 尺寸。Standalone 通过不代替 Host 通过。
- 回归：继续执行现有 [V4 日常播放器验证](../../maintenance/netease-v4-m2-daily-player-verification.md)与 [V3 界面验证](../../maintenance/netease-v3-ui-verification.md)，只对 V5 **明确变更的播放语义**更新旧预期。
- 文档：实现后同步 `reference`、`quick-start` 和验证矩阵；保留“实现完成 / 自动验证 / 用户验收”三个独立结论。V5 真正验收后再将此计划归档。

### 11.4 本地开发门禁与完整性

详细场景与失败注入规则见 [V5 专用验证计划](../../maintenance/netease-v5-ui-interaction-verification-plan.md)。沿用仓库的本地 PowerShell 入口；V5 实现已扩展里程碑参数、真实场景映射及独立资源证据，不以已有 V4 的测试数量代替新行为验证。

完整门禁应覆盖锁定依赖恢复、警告视为错误的 Debug 构建、全部适用单元/组件/集成测试、V5 场景到真实测试方法的映射、当前轮证据、文档链接及补丁格式。必需测试不得跳过；测试失败、报告缺失、旧报告复用、映射缺项、关键资源证据缺失时均失败退出，并对这些失败路径做门禁自测。

继续保留 V1–V4 回归；仅对第 5.3 节明确定义的播放语义更新旧断言，并补充迁移前后的行为说明。不能通过删测试、改成只断言“命令未抛异常”或放宽所有阈值换取通过。无需为静态颜色赋值等低风险细节编写机械单测；用主题/对比度与布局检查覆盖。

**本地开发门禁与 Windows CI、发布门禁是三个不同范围。** 当前只执行前者；不创建或触发 CI，不运行发布、签名、上传或发布包验收。将来正式发布再使用仓库既有发布流程。
