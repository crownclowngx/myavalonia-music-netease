日期：2026-09-25。V8-01～10 的推荐 / 榜单、作品、私人 FM、远端历史、账号寿命及测试门禁已接入。[当前契约](../../../reference/netease-music-discovery.md)说明最终行为，[人工验收](acceptance-20260925.md)单独记录未验范围。此次实施不使用 AIFLOW、Windows CI 或发布门禁，不部署、不推送、不发布。

## 实现与设计

遵循 SOLID，拆分只读目录、作品、远端记录、FM 内容与反馈端口。生产页面使用普通 MVVM；FM 内容服务不依赖音频或队列，原队列仍为唯一写入者。每 Document 导航独立，共享 FM / 播放服务。关键代码用中文注释说明取消、代次、预算和回执处理思路。

结构化歌曲身份由公共解析器统一补齐；不改变存储 schema。推荐歌单 / 榜单复用旧详情、收藏和完整歌单播放。FM 有显式开始 / 结束、有限预取、去重、竞争合并、暂停静默、跨批次不可播上限与一次偏好反馈；Next 零写入。远端读取不改本机历史，不调用播放上报接口。

初步复核修正了 FM 不可播链等待自身推进任务、假时钟等待注册时序、重新开始绕过限流、普通同曲意图退出 FM 后队列编辑状态未刷新等问题。针对这些边界增加实际受控任务、请求和媒体观察断言。

## 相对方案的具体落点

- 作品小端口与推荐目录类型共同放在 DiscoveryContracts.cs，没有为了文件名一致再拆一个仅几个声明的文件；读取与写入权限仍分开。
- 远端来源从本机历史页进入独立发现投影，原 HistoryWorkspace 与存储规则保持职责清晰。
- FM 原子接纳写在 PlaybackQueueCoordinator 的 partial 文件，复用同一锁；内容预算、网络、反馈留在独立服务，不创建第二个队列写入者。
- 证据按有独立观察过程的场景分为导航、FM 反馈、补取预算、终态竞争、跨批不可播、静默恢复 / 远端读取、历史、寿命、布局；每份均有本次 provenance。完整行为断言同时保留在 TRX 映射，不将汇总数冒充所有组合已经实机验证。
- 原路线图和日常播放器文档“最后一页关闭继续播放”的旧表述按既有租约代码修正为停止 / 释放；这不是 V8 改变原关闭策略。

真实账号、线上响应字段 / 权限、FM 偏好写入、真实 Host / 声音 / 物理输入未验证，M4 总验收不提前勾选。旧版待验项不因本轮回归通过而改成已验。
