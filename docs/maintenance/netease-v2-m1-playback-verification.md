## 1. 测试分层与夹具

V3 将默认本地开发入口扩展为 `-Milestone V3`，在本矩阵全量回归之上加入主题、布局和动效检查，详见[V3 专项矩阵](netease-v3-ui-verification.md)。M1 历史结果不改写。

| 层次 | 执行方式 | 证明范围 |
| --- | --- | --- |
| 协议与业务单测 | 固定输入、固定上游对照向量、受控 API 替身、TimeProvider | 编解码、结果分类、状态、分页和竞态 |
| HTTP / 媒体契约 | 真实 Flurl 适配配合 HttpTest；字节流与中断用受控 handler 或仅监听 loopback 的夹具 | 最终路径/参数/头、Cookie 隔离、逐段读取、限额、取消、截断及异常 |
| 文件与真实解码 | 测试专用目录、自生成或明确可使用的短音频样本、生产解码适配 | 文件所有权、媒体识别、实际 PCM/时长结果、格式失败与句柄释放 |
| 音频编排单测 | 遵守生产契约的可控音频替身；可以主动注入旧事件、故障和晚到结果 | 播放状态、指令顺序、事件隔离；不证明扬声器有声 |
| UI / 组合 | 真实 View 与页面模型、Headless、生产服务注册 | 编译绑定、按钮、投影、资源释放、多页面与依赖寿命 |
| 人工开发验收 | 真实账号、实际输出设备、Standalone 与真实 Host 分别操作 | 真实接口可用性、可听输出、设备行为和 Host 集成 |

默认自动套件不连接网易、不扫描用户会话、不要求可用音频设备、不启动 Host。测试构造解码器时不得隐式启动音频输出。Windows 本机的离线解码测试可以纳入开发门禁，这不属于 Windows CI。

首选引擎为 LibVLCSharp + LibVLC。离线解码夹具可以使用测试专用 PCM 回调收集样本，但必须经过生产使用的同一原生引擎和媒体打开路径；不把测试回调当作真实设备输出。自动测试使用明确指定的受控内置/外部运行库夹具，不读取用户保存的路径，不靠本机安装的 VLC 偶然通过。

已有测试项目为 [MusicNetEasePlugin.Tests](../../tests/MusicNetEasePlugin.Tests/MusicNetEasePlugin.Tests.csproj)，默认继续复用它。若引擎确实要求单独的本地集成进程，S0 记录必要性，S5 将该套件明确列为必跑开发检查，不用“跳过”冒充通过。

夹具要求：

- 协议向量来自固定上游及独立生成过程，固定随机输入仅用于测试；不能用待测 C# 实现生成自己的期望值。
- 音频样本包含格式、长度、来源/生成方法和摘要；真实网易缓存、账号 Cookie、签名 URL、公钥握手中的临时私钥不进入仓库。
- 并发测试用 TaskCompletionSource、屏障和可控时间精确控制顺序，不用固定 sleep 猜测竞态；每次等待有上限。
- 临时文件放在测试独占目录，校验最终状态与释放结果；不靠扫描用户数据证明无泄漏。
- Mock/替身需要表达设备启动失败、晚到事件和清理阻塞，不能只断言方法被调用几次。

## 2. P：音乐协议与请求契约

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| P01 | cloudsearch、song_detail、song_url_v1 请求 | 原生路径、协议、歌曲类型、分页、详情数组与 standard 参数正确；不调用 Enhanced 外壳路由 |
| P02 | 中文、emoji、空格、特殊字符与长歌曲 ID | 只编码一次，JSON/表单与固定向量一致，ID 不截断或丢精度 |
| P03 | xeapi 公钥初始化和必要依赖 | 缺失、畸形、失效状态明确失败或按约定有限重建；并发初始化不发布半成品，取消贯穿初始化请求 |
| P04 | xeapi 首次请求、协议会话复用与失效 | 请求与响应对应；新账号/新容器不会复用旧协议会话；迟到响应不能替换新密钥状态 |
| P05 | 明文、加密、压缩与畸形响应 | 正确解释选定端点支持的格式；解密、解压后仍受限额保护，未知结构不当成功 |
| P06 | HTTP 与正文 code 不同、限流、验证要求 | 保留必要分类与 Retry-After；单曲业务失败和 CDN 拒绝不自动变成账号失效；无无限 POST 重放 |

## 3. A：会话访问与账号隔离

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| A01 | 未登录、恢复中、已核验但保存失败 | 前两者不获取已登录音乐快照；内存已登录可正常调用，未记住状态保留 |
| A02 | 退出后以同一账号再次登录 | 新代次不同；旧请求即使 userId 相同也不能发布结果、Cookie 或播放状态 |
| A03 | 账号退出发生在详情/地址/缓冲请求期间 | 立即撤销后继请求资格并取消在途工作，晚到结果释放且不启动引擎 |
| A04 | 并发响应更新 Cookie / 协议状态 | 只有适用的账号代次和凭据版本能提交；旧响应不覆盖新凭据，业务 API 不自行落盘 |
| A05 | 新凭据保存失败、明确会话失效与断网 | 保留正确的内存/记住状态；明确失效才撤销，临时断网不删除有效凭据 |
| A06 | 登录提交、重试保存、取消补偿和退出回归 | 既有登录场景全部通过；没有第二份持久会话或全局 CookieJar；不同容器完全隔离 |

## 4. C：搜索、分页与详情

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| C01 | 空白输入、合法关键词、提交/回车 | 空白不请求；关键词规则一致，重复触发不会追加重复结果 |
| C02 | 首页、后续页、末页、空结果、总数不可靠 | 页码/offset 正确，明确结束条件；空页不无限补请求，不能把总数缺失当解析成功的全量结果 |
| C03 | A 搜索慢、B 搜索快、A 最后返回 | 仅 B 发布；取消、新关键词与换页代次一致，旧结果不覆盖新页面 |
| C04 | 详情、歌手/专辑缺失、可选字段缺失 | 必需 ID 不合格时受控失败；可选字段有占位；保持歌曲身份和时长单位一致 |
| C05 | 歌曲 A 详情慢，已选择 B | A 的详情和封面不能覆盖 B；详情失败不会清掉无关搜索结果 |
| C06 | 搜索、翻页失败与用户重试 | 加载状态能结束，错误可恢复；原有结果是否保留遵守页面契约，无静默混页 |

## 5. B：媒体请求、缓冲与文件

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| B01 | 合法资源、非法来源/协议、重定向链 | 逐跳校验、次数有限；不向媒体或重定向目标发送账号 Cookie、CSRF、xeapi 身份头 |
| B02 | Content-Length 缺失/伪造、超大流、非媒体错误页 | 以实际已读字节限额为准；错误页和异常格式不交给输出设备，不无限占用内存或磁盘 |
| B03 | 响应头超时、读取无进展、总预算耗尽 | 三类预算均能终止请求、关闭流并清理半成品；错误分类正确 |
| B04 | 预取消、读取中取消、写入后取消、引擎打开前取消 | 不发布已失效资源；响应、流、文件句柄各释放一次，取消不显示失败 |
| B05 | 目录不可写、空间不足、截断、写入和文件删除失败 | 不把半成品标可播；错误有有限摘要，删除失败进入受控清理而不循环阻塞 UI |
| B06 | 替换/停止/结束/失败后清理，进程异常残留 | 引擎先关句柄再清理文件；下一次清理不影响仍活动的实例或其他目录，拒绝越界路径 |
| B07 | 明确地址过期、一般 403、重取再次失败 | 只在规定场景最多重取一次；新的代次/停止优先；其他拒绝不无限重试或退出账号 |

## 6. L：单曲状态、控制与竞态

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| L01 | 选择 → 加载 → 引擎确认运行 | 引擎实际确认前不显示 Playing；当前位置、时长和状态一致 |
| L02 | 暂停、继续、停止、再次播放 | 暂停保留位置；停止释放资源并归零播放进度；再次播放解析当前有效资源 |
| L03 | A → B → C 快速切歌，A/B 各阶段迟到 | 最终仅 C 可接管；任何时刻最多一个音源，旧下载/旧事件不能恢复旧歌曲 |
| L04 | 加载中停止、Play/Stop/Pause 交错、同曲重复点击 | 最新合法意图生效；无排队复活、无重复启动，非法状态操作无副作用 |
| L05 | 自然结束、设备错误、解码器异步错误 | 分别进入 Ended/Failed；不自动下一首，不把正常结束当故障；清理完成 |
| L06 | 试听、无地址、部分权限字段缺失 | 试听范围与显示一致；无地址不启动；不凭元数据猜测完整权益或重复申请更高音质 |
| L07 | 音量边界、静音、暂停时改音量 | 约定范围内有效，非法数值处理一致；音量 0 不误报播放失败，不篡改系统全局音量 |
| L08 | 引擎进度乱序、停止后旧事件、UI 通知延迟 | 代次/快照版本生效；进度不跨歌曲，结束后无旧计时回写，不依赖 UI 线程同步等待 |
| L09 | 页面所有者关闭、其他页面关闭、账号退出和 Host 停止 | 仅正确所有者能取消页面播放；账号/Host 撤销所有音乐工作；释放后无活动回调或重新出声 |

## 7. E：真实引擎与离线解码

| 编号 | 场景 | 关键断言 / 验证方式 |
| --- | --- | --- |
| E01 | 至少一种目标格式的短样本由生产解码适配打开 | 产生有效 PCM，采样率、通道、帧数或时长落在合理范围；不用替身代替真实解码 |
| E02 | 不支持格式、损坏/截断样本 | 明确失败并释放文件，不能仅凭扩展名返回可播放 |
| E03 | 复用引擎连续换曲、最终释放、文件占用和事件退订 | 媒体逐次释放，引擎由容器最终释放；可删除样本副本，无旧回调/重复销毁错误；反复启停不死锁，记录句柄/线程资源趋势 |
| E04 | 内置/指定目录缺少 LibVLC、模块或配套库 | 初始化前按约定检查两种来源并反馈问题，不扫描未指定目录；本地必测夹具缺失则检查失败，不标跳过后通过 |
| E05 | 设备不可用、启动失败、播放中失去输出 | 替身覆盖稳定状态语义；实际设备行为由 R 类验证，二者证据分开 |
| E06 | RID、架构与内置/指定目录探测 | 主库、配套库及必需模块按兼容清单检查；错误架构/缺文件明确失败；内置依据入口程序集，指定目录规范化且来源准确 |
| E07 | 初始化并发、失败后配置与容器停止竞态 | 不发布半初始化实例；静态检查失败可修正重检，原生加载尝试后路径冻结、变更需重启；停止后不再启动，不改 Host 全局搜索路径 |

E01–E04 尽量保持无声卡依赖。S0 若证明特定解码项必须独立运行，应在最终 M1 门禁中明确加入该开发集成套件；实际出声始终按 R 类另记。

E06/E07 的路径和生命周期契约使用受控夹具验证；原生库不可卸载或会污染后续用例的故障探针使用隔离的测试进程，避免测试顺序掩盖错误。测试进程隔离不改变生产播放器必须在 Host 进程内运行的约定。

## 8. T：路径设置与账号 Tool

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| T01 | 内置有效，同时存在有效/无效/空的配置目录 | 始终选内置；保存的外部值不丢失；显示实际来源和未采用原因 |
| T02 | 内置缺失/不完整，指定目录有效；两者均不可用 | 前者在原生初始化前选指定目录并保留内置问题；后者只禁用播放，账号、搜索和 Tool 仍可用 |
| T03 | 相对路径、单个 DLL、错误架构、缺模块、不可读目录 | 按输入契约拒绝并汇总可识别问题；不加载 DLL，不扫描其他插件或 PATH |
| T04 | 草稿 A 检测未结束即改为 B，选择器迟到或重复点击 | 只发布当前草稿/请求的结果；检测不保存或出声；过期检查不能为新草稿授予有效状态 |
| T05 | 保存成功、写入/替换失败、畸形配置、清空和下次启动失效 | 原子保存及恢复策略明确；失败保留旧值，畸形配置报问题；清空不删外部目录，失效路径保留以便修复 |
| T06 | 初始化前修改；加载开始/成功/失败后再修改 | 初始化前使用最新有效候选；此后保存为下次启动值，当前加载不热切换；媒体失败不误报为运行库配置失败 |
| T07 | Tool 账号摘要、登录入口引导、退出与修改路径 | 读取同一 LoginSnapshot，提示从“新建”打开原登录页；退出撤销音乐但保留路径，修改路径不清除会话。SDK 3.4.1 无运行时 Document 打开端口 |
| T08 | 无音乐 Document 时打开 Tool，隐藏/重开及多次创建 View | 同一个 Tool 模型与设置源；不因显示 Tool 初始化 LibVLC、自动登录或播放；隐藏保留草稿，不释放共享服务 |
| T09 | 用户指定共享目录，自身清理/关闭/配置清空 | 仅只读使用库文件，不删除/改写共享目录；不拥有其他插件的引擎、音量或账号；真共存由 R10 验证 |

T 类自动测试隔离配置目录与运行库夹具。文件内容、失败保存后的状态和服务调用边界均须有行为断言，不能仅检查是否出现某个类名。

## 9. U / D：界面、组合与设计审查

| 编号 | 场景 | 关键断言 |
| --- | --- | --- |
| U01 | 未登录、已登录、搜索加载/空/失败与各播放状态 | 登录入口保留，按钮可执行性正确；播放加载不误用登录状态文本 |
| U02 | 生产 View 的编译绑定与不同窗口尺寸 | 搜索、结果分页、歌曲信息、试听和控制可见；无裁切/遮挡，实际 Headless 图人工检查 |
| U03 | 封面失败、快速换歌、视图临时卸载和重挂 | 占位图有效；旧图片不覆盖新歌，Bitmap 生命周期完整；视觉树拆卸不冒充 Document 关闭 |
| U04 | 多页面共享播放器、各自搜索与真正关闭 | 只有一个共享引擎；搜索局部状态独立；发起播放页面关闭停止它，其他页面关闭不干扰 |
| U05 | 容器隔离、Host 异步停止与同步 Dispose | 对象复用/隔离符合声明；无必须回 UI 的同步等待、重复释放或关机后请求 |
| U06 | 慢网络/文件读取/引擎初始化 | 操作可取消，UI 调度不阻塞；异常不成为未处理的 async void 故障 |
| U07 | Tool 与 Document View 重复 attach/detach、DataContext 切换 | 订阅无累积，旧回调不更新新 View；不重发 Play/Stop，不创建新引擎；最终由正确所有者释放 |
| U08 | 目录选择器挂起时 Tool 隐藏、浮动窗口关闭或绑定改变 | 选择器防重入；失效 View/请求的返回值不覆盖新草稿；关闭 Tool 不冒充 Document ClosingToken |
| D01 | SOLID 与依赖方向审查 | 按主方案分工核对；业务类不依赖具体 Flurl/音频库，不用容器定位服务；平台加载差异留在 Infrastructure |
| D02 | 朴素设计与中文注释审查 | 抽象有实际替换边界；关键状态、线程、所有权、协议和设计原因有准确中文说明 |
| D03 | 日志与持久化审查 | 凭据、临时 URL 和原始响应不进入日志/展示；不把媒体缓冲当永久曲库 |
| D04 | 文档与功能状态审查 | 当前契约、快速开始、方案、矩阵和导航一致；不以测试用例编号数量代替实际通过数 |

D 类需要真实代码审查结论；不写搜索某个类名、中文注释数量或代码文本的测试来代替设计审查。

自动边界：系统选择器由受控返回替换，真实 View 仍执行防重入、挂载/重绑/草稿过期保护；设备故障使用音频替身；目录写入失败用真实文件占用/无效目录，未实际填满磁盘或变更系统 ACL；原生故障验证空/坏媒体与静态缺库/架构。真实设备拔除、系统文件夹对话框操作、双插件同时运行和完整 Host 退出仍需 R 类验证。

M1 门禁已核对场景映射与本次测试发现/执行结果。一个测试可以覆盖多个场景；场景清单不等于用例数。Trait 用于检索，映射必须对应真实行为断言，不能只靠标签通过。

## 11. G：本地开发门禁及其自测

已扩展 [verify-development.ps1](../../tools/verify-development.ps1)、[DevelopmentChecks.ps1](../../tools/DevelopmentChecks.ps1) 和[门禁自测](../../tools/test-development-gate.ps1)，支持并默认选择 `-Milestone M1`，增加 M1 映射和解码/图像证据校验；复用同一套 restore/build/test 实现。

无参数入口仍可使用；`-Milestone Login` 仍执行全量套件，只省略 M1 附加映射/产物判定。M1 开发模式按以下要求执行，人工验收不由脚本伪造：

| 编号 | 检查 / 注入失败 | 必须表现 |
| --- | --- | --- |
| G01 | 锁定还原失败、Debug 警告/错误、进程非零退出或超时 | 整轮失败；错误不被后续命令成功覆盖，超时进程及其子进程收口 |
| G02 | 全量测试发现与执行 | 执行新增音乐测试及既有登录回归；本轮全部必测套件完成，禁止零测试或过滤掉登录后宣称全量通过 |
| G03 | M1 映射空、缺场景、测试被重命名/漏执行 | 包括新增 T 类及 U07/U08，必须核对实际执行；仅旧登录测试通过不能通过 M1 门禁 |
| G04 | 失败、取消、跳过、未完成测试 | 任一必测项出现这些状态即失败；不能用 exitCode=0 或部分套件的成功掩盖 |
| G05 | 缺失、旧、截断、统计不一致或路径不属本轮的 TRX | 拒绝报告；时间、结果条数、Passed 状态与统计一致，独立结果目录防止混用 |
| G06 | 本仓坏文档链接、锚点、差异格式 | 明确失败；历史记录和新增文件纳入检查，邻仓参考按既有规则单列 |
| G07 | 默认离线与工作目录隔离 | 网络适配测试无未预期外网请求，文件仅写测试目录；套件初始化不读取真实会话或启动输出设备 |
| G08 | 证据缺项、把自动测试冒充真实输出/Host 验证 | 记录缺失或分类错误不能成为通过结论；仅自动检查的报告明确未执行真实账号/输出/Host/发布活动 |

G01、G04、G05 复用并扩展已有失败注入；G03 为本阶段新增的关键门禁可靠性用例。门禁自测验证真实报告解析与编排行为，不仅匹配脚本字符串。设计审查和人工验收由关联记录表达，脚本不伪造“已经审查”。

建议 M1 每轮结果目录为 `TestResults/NetEaseM1/<UTC时间-随机ID>/`，包含本轮 TRX、实际执行的套件及场景映射摘要、生产 View 渲染图与 `verification.json`。保留 revision、dirty 状态、命令、环境、开始/结束时间、测试统计和各验证活动状态；无须在导航页复制测试数。

门禁执行顺序：脚本自测 → locked restore → Debug 零警告构建 → 全量自动套件与必要离线解码套件 → TRX/场景映射 → 文档检查 → 生成结果。真实接口和有声输出不在默认单测中自动触发。

无需执行 Windows CI、Release 构建、发布 ZIP、Windows 发布 Smoke、seal、发布覆盖率或发布重复性检查。新增包时先正常还原并审查 lock 更新，再使用 locked-mode。

## 12. R：真实账号、音频与 Host 开发验收

| 编号 | 操作 | 必须记录的结果 |
| --- | --- | --- |
| R01 | 使用已登录账号搜索一首已知可播歌曲并查看详情 | 真实搜索结果、详情与选择身份一致；记录日期、接口基线和概括性账号条件 |
| R02 | 点击播放，等待加载完成并确认出声 | 实际格式/音质、临时文件输入路径方案、加载耗时、实际可听输出；不记录资源 URL 或缓存音频 |
| R03 | 暂停、继续、停止、调音量、自然结束和再次播放 | 用户可感知的行为正确，停止后无残余播放；如为试听样本，其时长与显示一致 |
| R04 | 快速切 A/B，并在加载中停止 | 最终仅最新歌曲出声；停止后晚到数据不恢复播放，无重复音源 |
| R05 | 在 Standalone 中关闭发起页面/窗口，再次启动 | 正确停止与释放；无遗留文件占用；重启保留原登录恢复规则，不自动播放上一曲 |
| R06 | 真实 Host 的开发产物加载、多页面、关闭与退出进程 | 依赖可加载、只有一个播放器、页面所有权正确，Host 退出后无请求和音频；单独于 Standalone 记录 |
| R07 | 播放/加载时退出账号，包含远端退出失败的受控场景 | 本地音频停止，搜索/播放数据清除，旧资源不复活；既有会话清理提示正确 |
| R08 | 可取得的试听、不可播、网络中断及输出设备失败样本 | 实际结果与提示一致；无真实样本的条件项注明未覆盖，并关联相应自动失败分支证据 |
| R09 | 内置库模式，以及无内置库时在 Tool 配置有效目录 | 两种方式均出声，Tool 显示来源/路径与真实加载一致；内置模式随插件目录移动仍有效；不启动外部播放器 |
| R10 | 两插件各自内置，以及音乐指定视频实际使用的库目录；各按两种顺序加载 | 两种部署组合分别留证，关闭一方不影响另一方；架构/版本冲突可诊断，实际模块来源符合配置 |
| R11 | 播放中修改目录、保存、隐藏/重开 Tool、重启 Host；随后退出账号 | 保存不热切换或打断音频；重启后按优先级选择，账号退出保留路径；缺库仍能操作账号与设置 |
| R12 | Playing/Paused 下分别进行 20 次 Document 停靠/浮动/切换与 Tool 自动隐藏/重开，最后关闭所有者 | 播放态持续、暂停态不自启，未重建引擎或重复命令；Tool 浮动窗口关闭仅隐藏；真正关闭所有者才停止 |
| R13 | 预热后反复开关 Document/Tool、切歌和最终 Host 退出 | 分阶段记录引擎/播放器/Media/订阅数及句柄/线程趋势；容器内复用引擎，旧 Media 和文件句柄回收，无重复回调或死锁 |

R01–R07、R09–R13 是 Windows x64 M1 的核心开发验收。R08 按真实样本分项记录。R12 使用真实 Host；Headless 只能补充验证订阅和状态。R13 的增长需区分引擎预热与每轮持续泄漏，明确调查持续增长，不凭托管计数归零宣称原生资源全部释放，也不照搬视频发布门禁阈值。
