## 2. 具体取舍与边界

- 队列断点使用**音乐区** ≥1120×550 DIP，对应通常含账号栏的 Document 高约 600；窄/矮 Dock 均收为内容页，不仅按宽度判断。
- 播放模式保留四项明确名称的常驻 ComboBox，避免只用图标让用户猜测。上下首/播放/暂停/更多使用统一自绘几何。
- SDK 3.4.1 没有公开 Tool 激活端口；账号菜单在当前 Document 展示同一个容器单例设置模型，独立 Tool 注册仍可使用。设置遮挡音乐内容时暂停其新增视觉工作，返回不重新创建播放器。
- 图片只接收已知尺寸的 PNG/JPEG，源像素限 4,194,304，最长边缩略解码至 256，比方案 512 上限保守；未知/动画格式显示矢量占位。CDN 仍使用既有 160 档。
- 新增背景过渡和短反馈有明确收口，没有 60 Hz 进度插值或装饰循环时钟。二维码与登录流程独立，不受关闭封面的开关影响。
- 软件内的 TextPresenter 预编辑状态已用实际输入事件验证；物理中文输入法、Host Dock 浮动与多 DPI 必须另做实机验收。

## 3. 责任与所有权

`MusicWorkspace` 聚焦搜索和组合；`MusicNavigation` 只记导航；`PlayerBarWorkspace` 与 `TimelineWorkspace` 分别处理播放事实和定位草稿。共享队列的原子操作仍属于 `PlaybackQueueCoordinator`，页面不拼装多个命令模拟原子操作。

`IAccountImageSource` 是无凭据网络端口，`AccountImageCache` 装饰下载并控制并发/压缩预算；表现层 `ArtworkCache` 拥有位图，`ArtworkImage` 按可见性申请和归还租约。账户撤销清理有代次保护；外部取消不提前 Dispose 仍被任务使用的 CTS。UI 回调只投递，不要求后台下载等待 UI 才能结束。

采用普通构造注入、MVVM、缓存装饰器和租约，没有事件总线、通用仓储或页面服务定位器。关键注释为中文，说明锁边界、迟到响应、模板继承、输入路由、跨页面引用和回收理由。

## 5. 同条件资源观测

[原始 V4 样本](../archive/records/netease-v5/assets/v4-baseline.json)、[原始 V5 样本](../archive/records/netease-v5/assets/v5-observation.json)、[汇总 JSON](../archive/records/netease-v5/assets/resource-comparison.json)。同机 Windows x64、.NET 10.0.10、Avalonia Headless + Skia；1200×720、10,000 队列项、1,000 行歌词，假网络/音频；每场景 60 秒，三轮，以下取中位数。

| 场景 | V4 Private Bytes | V5 Private Bytes | V4 单核 CPU | V5 单核 CPU | 60 秒托管分配 V4 → V5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 暂停且可见 | 49.59 MiB | 52.65 MiB | 4.60% | 6.65% | 1.25 → 1.19 MiB |
| 歌词可见播放 | 51.84 MiB | 52.77 MiB | 8.33% | 10.93% | 55.90 → 51.52 MiB |
| 隐藏仍播放 | 51.95 MiB | 52.72 MiB | 4.67% | 5.33% | 3.55 → 1.48 MiB |

内存中位增量最大约 **3.06 MiB**，低于 +32 MiB 建议值。打开队列并返回搜索的热态配对耗时 p95 中位数 **10.22 → 14.65 ms**，低于 100/150 ms 建议值；V5 为保持同样的最终搜索状态额外显式关闭侧栏。隐藏场景 CPU 增量约 0.66 个百分点，托管分配降低约 58%。

**暂停可见场景 CPU 增量约 2.05 个百分点，未达到建议的 +1 个百分点。** 此采样每 200 ms 主动强制 Headless 布局/绘制，不能称为实际 Host 的静止空闲 CPU，也不是 GPU/帧耗时测量；更大歌词和更丰富布局的重绘成本已如实保留。确定性测试另外证明隐藏时没有新增歌词/播放条进度通知。未据此声称“所有性能指标达标”。真实 Host 空闲、滚动 p95、GPU 和 DPI 仍待实机测量。

采样结束后仅修正可选图片回调收口、设置覆盖时可见性及测试文档；本采样没有联网图片，也未打开设置。性能报告保留其自身源码指纹，最终开发门禁使用最终源码指纹，两个来源不混写。

当前矢量/主题静态资产共 **8,725 字节**，3 个字典；产品内置新增装饰位图/字体/视频为 0。图片压缩缓存 8 MiB、最多两个下载、位图 24 项/16 MiB 上限由确定性测试分别覆盖，全部占用时回退占位。

## 6. 部署与交付范围

已用独立 Debug 输出、`IncludeLibVlcRuntime=false` 编译，并经 `DeployManagedPlugin` 部署到用户指定的 `D:\data\avalonia\Controls\MusicNetEasePlugin`。12 个文件的名称、长度、SHA256 与干净暂存产物一致；不携带原生 libVLC，保留必要的托管 LibVLCSharp。部署前后公共运行库 425 个文件摘要相同。详见[专用部署与清理记录](../archive/records/netease-v5/deployment-20260923.md)。

相同无原生库 Debug 布局由 6,383,814 增至 6,528,114 字节，增加 **144,300 字节（约 140.92 KiB / 2.26%）**；其中入口 DLL 增加 115,200 字节，PDB 增加 29,100 字节，其余文件摘要未变。

标准清理删除 4,130 个文件、约 **1.915 GiB**。用户要求同时删除旧版本副本，但递归删除被自动审批审核以 `blocked by policy` 拒绝；没有改用其他工具重试。清理范围仍余 608 个文件、约 166.90 MiB，含旧版本备份与部署暂存、还原缓存；不能称为全部清空。已保留精确路径与大小，当前部署清理后再次校验一致。

本次没有真实账号联网探针、实际声卡听音、真实 Host Dock / 多 DPI / 物理 IME 验收，也没有运行 Windows CI 或正式发布门禁。这些边界不能由 Headless 截图或 V1–V4 验收替代。核心代码完成与产品实机验收分别记录。
