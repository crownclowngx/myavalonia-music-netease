> 本矩阵对应 `-Milestone V5` 的证据要求，包含 M1/V3/V4 回归；当前默认完整检查为 `-Milestone V6`，继续包含本矩阵，命令见[验证指南](verification.md)。历史复核中的 C01–C08 已由 V6 承接，性能及实机事项持续维护在[待验清单](netease-v5-v6-acceptance.md)。原 V5 布局预期由 V6 明确变更的部分，以 V6 矩阵与当前界面契约为准。

## 1. 范围与通过条件

验证 V5 是否在保持现有听歌能力的前提下，提高操作效率、状态辨识和窄屏可用性，并遵守资源预算。范围覆盖方案阶段 A–D；阶段 E 的取色、平滑歌词、拖拽和撤销仅在实际选择实现时加入对应场景。

每个场景都记录“未实现 / 待验证 / 自动通过 / 实机通过 / 失败”中的实际状态。自动化证据和真实 Host 证据分别填写；不能把 Headless 截图、模拟音频或测试数量写成真实声卡和 Dock 验收通过。

通过条件：必需场景都有对应实现与证据；本地构建及全部适用测试通过；无必需测试跳过；资源目标有同机对比结果；手工项目有实际结论。若保留未测/未达标项，列明影响，不能将整项标为完成。

## 2. 自动化场景矩阵

下列编号是稳定场景编号；30 项行为场景映射到 `tools/v5-test-map.json` 的真实测试方法，U04 由 `Assert-V5Assets` 检查产品资源。一条场景可由多个测试共同覆盖；四种播放模式、账号变化和错误分类用必要的参数化用例覆盖，不依赖恰好固定的测试总数。

### 2.1 播放语义与一致性

| 编号 | 触发与边界 | 必须验证的结果 |
| --- | --- | --- |
| V5-Q01 | 搜索、歌单、历史立即播放；空/非空队列 | 非空时插在当前项后并播放；原条目相对顺序不变；三个来源语义一致；空队列正常建立 |
| V5-Q02 | 立即播放当前同曲；正在播/加载/暂停/停止 | 不重复入队；按状态继续或启动；不会双重打开媒体；错误状态重试有明确结果 |
| V5-Q03 | 四种播放模式，已有“下一首”优先项；连续临时播放 | 优先规则、原顺序、随机历史和结束推进符合方案；明确用户意图优先；不会误清空优先项 |
| V5-Q04 | 相同 TrackId 在多个位置；重复 EntryId；容量达到上限 | TrackId 不冒充位置身份；拒绝重复 EntryId/超限时队列不发生部分修改 |
| V5-Q05 | 两个 Document 快速点播；旧媒体加载迟到 | 最新有效意图生效；旧请求不能覆盖新曲目、状态或账号；每次意图只执行一次 |
| V5-Q06 | 临时歌曲不可播、网络失败、试听；推进中退出账号 | 按既有错误分类处理；原队列仍在；无无界跳曲/重试；账号失效结果不写回 |
| V5-Q07 | 播放全部/从这里播放；分页未完成或快照不完整 | 只有显式整单意图替换队列；使用完整 ID 快照和准确起点；不完整时禁用并说明原因 |
| V5-Q08 | 行内、Enter、双击、菜单、右键触发；选择行与播放行不同 | 相同动作调用同一规则且只执行一次；单击只选择；“选中”与“正在播放”可独立显示 |

## 3. 测试分层与实现约束

- **纯单元测试：** 队列规则、导航、偏好迁移、缓存预算与取消判断，不依赖网络、真实账号、Avalonia 窗口或声卡。通过可控完成顺序制造并发，不靠长时间 sleep 偶然撞到竞态。
- **组件测试：** 使用项目现有 Avalonia 测试设施，经过真实控件事件验证绑定、焦点、菜单、手势和命中区域；不能只直接调用命令就宣称输入交互通过。
- **集成回归：** 真实模块 Configure 后检查贡献根不进入私有 DI 集合；验证 Host 追加 Tool singleton / Document scoped 后设置共享与关页重开。普通 BuildServiceProvider 成功不能代替 Host 注册所有权检查。保留现有会话、HTTP、文件存储及 LibVLC 离线用例，检查新界面意图没有破坏既有资源与账号边界。
- **架构审查：** 按方案第 9 节检查 SOLID、资源所有权和中文注释。测试替身必须遵守真实契约；不通过大量 Mock 验证内部调用顺序替代用户可见结果。
- **风险取舍：** 状态机、并发、播放/定位和缓存预算属于重点；静态间距/颜色优先用实际布局和视觉检查，不给每个常量写复述实现的单元测试。

每个修复应有能在修复前失败、修复后通过的相关用例。截图通过不能代替绑定和状态断言；断言通过也不能代替真实主题、DPI 和易用性复核。

## 4. 本地门禁计划

已在现有脚本上增量扩展 V5 参数、场景映射及必要证据校验，继续复用已有 V1–V4 检查，不维护第二套互相漂移的入口。新增映射应列出真实的完整测试方法名；必需编号不得以占位字符串计为覆盖。

执行顺序：门禁自测 → 锁定依赖恢复 → Debug 构建且警告视为错误 → 全部适用测试 → TRX/场景/资源证据检查 → Markdown 链接和补丁格式 → 验证期间源码未变化检查。

| 门禁自测编号 | 注入失败 | 必须结果 |
| --- | --- | --- |
| V5-G01 | 测试失败、跳过、零执行或 TRX 统计与逐条结果不符 | 非零退出，不输出通过结论 |
| V5-G02 | 缺必需场景、映射到不存在的方法、只留下同名展示字符串 | 不视为覆盖，明确指出缺项 |
| V5-G03 | 复用旧 TRX/截图/资源 JSON，运行编号或源码指纹不同 | 拒绝跨轮拼证据；当前截图必须有当前轮元数据 |
| V5-G04 | 缺图片预算计数、销毁后引用、截图尺寸等必要字段或超过硬上限 | 缺失不能当作 0；按规则失败并说明原因 |
| V5-G05 | 工具超时/异常退出、验证时改源码、无效相对文档链接 | 中止并给出具体阶段，不吞掉错误或沿用旧成功记录 |

证据至少含运行编号、开始/结束时间、Git 提交、工作区 dirty 状态、源码摘要、执行环境、各场景结果和文件摘要。真实账号、真实声卡、Host/Dock、性能测量分别标记；任何一个字段不能代替其余字段。

当前已有的可执行回归入口：

```powershell
pwsh -NoProfile -File tools/verify-development.ps1 -Milestone V4
```

纯文档改动使用以下检查；不得为了让文档中的 V5 命令“看起来能跑”而增加一个空壳参数：

```powershell
. ./tools/DevelopmentChecks.ps1
Assert-MarkdownLinks (Get-Location).Path
git diff --check
```

不运行 Windows CI、正式发布、签名、上传、部署及 ZIP 发布门禁。开发阶段可以统计本地构建产物大小；正式发布时再测同条件分发 ZIP 增量。

## 5. 实机与性能专项

| 类别 | 必测环境/动作 | 记录方式 |
| --- | --- | --- |
| 宿主布局 | 真实 Host 的 Dock、浮窗、拖出/回停；多 Document；Tool 的 280/320/420×900、640×240 | 环境版本、操作步骤、结果与对应截图；Standalone 结果分开写 |
| 显示与主题 | 100%/125%/150%/200% DPI，深浅主题、长中文文本、所在窗口主题切换 | 记录物理尺寸及换算后的 DIP，不把 520 物理像素当作 520 DIP |
| 输入与辅助功能 | 鼠标、仅键盘、中文输入法组合、屏幕阅读器可访问名称 | 对焦点归还、状态播报频率和不可用原因逐项确认 |
| 易用性 | 搜索播放、下一首、打开/返回歌单、恢复浏览、关闭封面 | 记录完成路径和卡住位置；用户不需知道 EntryId、epoch、运行库候选等内部概念 |
| 资源对比 | 相同机器/数据/音频/构建条件下 V4 与 V5，暂停/可见歌词/隐藏各 60 秒 | Private Bytes、进程 CPU 时间、分配趋势、请求/图片/计时器数量；预热后至少三轮 |
| 延迟与帧 | 热态导航、滚动、队列开合、10,000 项小操作 | 记录样本量、p50/p95 和停顿；每轮收集足量重复交互/帧样本，不能用三个单值估算可靠 p95 |

资源阈值以方案第 7 节为唯一来源；测不到的指标写“未测”。对比前后的音频格式、设备、缓存和供电模式保持一致。硬预算失败先减少装饰与额外工作，不能擅自提高阈值。

## 6. 结果与文档收口模板

实施阶段新增带日期的 V5 专用记录，至少包含：

1. 实现范围、源码提交和与计划的差异；哪些增强项未选择。
2. SOLID 责任分配、资源所有权、关键中文设计注释所在文件。
3. 本地门禁命令、TRX/运行编号、场景映射、失败注入结果。
4. 同机资源基线与 V5 数据、样本条件、未测/未达标项及处理。
5. 三尺寸双色截图和真实 Host/DPI/输入验证结果，各自证据独立。
6. 同步的 `reference`、`quick-start`、文档导航和用户确认状态。

当前实施、测试数量、门禁证据及性能结果只引用 V5 专用实施记录。G01–G05 由 PowerShell 失败注入自测覆盖，不伪装为 TRX 业务用例；真实 Host / DPI / 物理 IME 保持独立验收。
