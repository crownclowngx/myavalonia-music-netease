## 2. 设计思路与边界

`MusicNavigation` 仅保存每个 Document 的浏览枚举与侧栏枚举；`MusicView` 负责内容区布局、宽度手势和焦点；`DrawerTransition` 负责有限过渡。关闭内容立即停用输入及视觉更新，外壳才完成退场。偏好共享，开关和浏览状态不跨 Document 混用。

歌词时间事实仍由共享 `LyricsCoordinator` 给出，`LyricsWorkspace` 只投影和验证定位意图。预览不请求新歌词。先完成布局、必要时再实现目标行，避免零尺寸时请求虚拟容器造成重复显示；远距离跳转不遍历所有行。

`PlayerBarWorkspace` 管播放投影，`TimelineWorkspace` 管草稿与定位；`DelayedBusy` 管一个可取消延迟，业务忙碌无需等待 150ms。追加反馈来自 `QueueAdditionResult`，而不是对队列总数作推测。恢复提示拥有独立身份，收起只改变页面提示。

`QueueDragGesture` 只管理指针捕获、预览及有限边缘计时器；`PlaybackQueueCoordinator` 是唯一结构写入者。按 EntryId 区分重复歌曲，以 QueueRevision/AccountEpoch 拒绝旧拖动。单步撤销记录必要逆操作，不存整个播放器快照，不引入通用历史栈。移除当前项后撤销只补回条目，不切回旧曲；移除最后一项后补回仍停止，须选中播放。资料补全可保留撤销资格，后续结构、模式、导航变化及账号切换使旧资格失效；已消费播放历史不伪造回滚。

`SongRowView` 共享信息展示，窄/宽转换保留三列身份，仅改变宽度；完整资料弹层在回收/拆卸时关闭。歌单封面复用原有租约和图片缓存，不增加新下载器。

采用普通 MVVM、构造注入、枚举和值记录；中文注释解释竞态、身份和资源寿命。没有新增框架、事件总线、第二个播放器或 Host 内部依赖，保持 SOLID 的职责与依赖边界。
