## 1. 验证分层与统一规则

| 层次 | 验证对象 | 工具与边界 |
| --- | --- | --- |
| 单元测试 | 输入 / 权限规则、差集、结果分类、回查预算、账号与并发 | 现有 xUnit、Fake、`FakeTimeProvider`、受控任务完成顺序；不使用真实网络；业务时间由可控时钟推进，短暂调度让步不代替断言 |
| 协议 / HTTP 测试 | 固定端点、协议参数、令牌位置、业务码、响应完整性、Cookie 提交 | 现有协议向量与 Flurl 拦截夹具；合成会话 / 令牌，不读取用户保存会话 |
| UI 自动测试 | 生产 View 绑定、菜单、确认、焦点、键盘、布局和生命周期 | Avalonia Headless / Skia；真实生产控件加 Fake 端口，不制作替代 UI 证明生产交互 |
| 本地门禁自测 | 失败 / 跳过 / 缺场景 / 旧证据被拒绝 | PowerShell 失败注入；自测临时证据不能归档为业务验收 |
| 人工实测 | 真实账号写后回查、官方客户端交叉核对、Host / Dock、物理输入 | 独立带日期记录；不纳入默认自动测试，不从 Headless 或模拟响应外推 |

自动业务测试必须离线：使用隔离临时目录、合成 AccountId / Epoch、固定数据和受控响应，禁止自动访问网易业务、保存会话、真实私有歌单或系统音频输出。凡返回 `NeedsRecheck`、部分结果或取消的用例，既断言最终显示，也断言写请求次数、目标参数、快照版本和事件次数。

下面 A / L / S / E / T / D / C / U / R 共 46 个自动业务场景必须映射到真实测试方法。G 为门禁自测，H 为人工验收；它们各有执行记录，不能只加 Trait 让它们出现在业务 TRX 里。

## 2. 接口、权限与输入基线

| ID | 必须覆盖的情况 | 核心断言 |
| --- | --- | --- |
| V7-A01 | 所有 M3 读 / 写端点的路径、协议、布尔 / 数组编码、普通歌单类型和隐私参数 | 请求与已核定契约一致；不调用 Node 外壳路由；所有 mutation 均无自动重试 |
| V7-A02 | 收藏令牌成功、获取失败、取消、过期响应及错账号响应 | 必需位置正确；失败时收藏写请求数为 0；令牌不跨代次复用、不进入日志 / 快照 |
| V7-A03 | HTTP 非 200、业务拒绝、429、301 / 401、验证要求、无效 JSON、缺字段、超预算及不匹配 ID | 未知业务码不作成功；会话失效只使当前会话失效；不确定发送进入回查，明确拒绝不盲目重发 |
| V7-A04 | 自有普通、他人、内置喜欢、共享、类型 / creator 缺失、私密可访问及权限已变化 | 仅已知允许的操作可写；UI 与应用层双重校验；不能按名称、首项或旧 `IsOwned` 推测全部权限 |
| V7-A05 | ID 正负、0、溢出；名称 / 描述空白、换行、中文、emoji、非法控制字符及上限前 / 中 / 后；集合去重和上限 | UTF-16 长度不冒充 Unicode 标量数量；空描述清空与未知描述不同；无效请求数为 0 |
| V7-A06 | Fake 与真实适配器对取消、未知 / 不完整、拒绝、回执和部分结果的共同契约 | 同一组契约断言用于两种边界；DTO / `ToString` / 错误 / 测试报告无凭据和原始私人响应 |

每个端点至少有合法成功、合法拒绝和损坏响应三类夹具；未知码、发送后取消 / 超时还需不确定结果夹具。上游模块只有参数实现而没有响应样本的字段，在取得依据前不编造线上契约。

## 3. 喜欢与收藏

| ID | 必须覆盖的情况 | 核心断言 |
| --- | --- | --- |
| V7-L01 | 喜欢集合为空、有值、重复 ID、缺失、读取失败、结构不完整和超过 50,000 / 1 MiB 预算 | 已知空集合才表示全部未喜欢；不完整 / 失败不能变成全未喜欢；同账号同一在途读取共享 |
| V7-L02 | 喜欢、取消喜欢、原本即目标状态、业务拒绝、回查确认成功 | 参数是明确目标布尔值；只有确认后改变持久显示；无变化结果不发写请求 |
| V7-L03 | 双击、连续相反点击、两个 Document 同时操作同一歌曲或不同歌曲 | 同账号库写入在途不超过 1；其余返回忙碌且不延后发送；不会把重复点击解释为反向写 |
| V7-L04 | 搜索 / 歌单 / 队列 / 历史 / 播放条出现同一 ID；队列含重复条目；换曲期间回包；内置喜欢歌单正在显示 | 已确认喜欢状态按 ID 同步所有入口；内置歌单详情 / 计数重新读取且保留服务端顺序；旧曲结果不赋给新曲，喜欢不导致播放或重开媒体 |
| V7-L05 | 写后旧集合、短期不一致、回查失败和仅点击“重新读取结果” | 自动回查有界；原状态标记待核实；重新读取不产生第二次写请求 |
| V7-S01 | 正常 ID 打开未收藏歌单、格式错误、不存在、不可访问、导航先后乱序 | 新增收藏有可达入口；无效 ID 不联网；旧详情不覆盖新导航 |
| V7-S02 | 真实收藏字段缺失、目录第一页缺项、目录截断、详情与旧目录冲突 | 不把“未出现在已加载列表”当未收藏；使用已核定的权威状态 |
| V7-S03 | 收藏成功 / 已收藏 / 取消成功 / 已取消，写后目录重复或重排 | 目标状态确认后按 ID 合并；目录与详情一致；分页偏移重建，不重复 / 漏掉同一条目 |
| V7-S04 | 他人歌单取消后仍可访问 / 不可访问，多 Document 查看相同歌单 | 详情按访问状态保留或提示；导航合理；当前队列、播放代次和位置不受影响 |
| V7-S05 | 自有歌单误收藏、在途重复点击、限流 / 验证要求及超时 | 无效自收藏请求为 0；不自动换端点；不越过 Retry-After；超时不重复写 |

## 4. 创建、编辑、曲目管理与删除

| ID | 必须覆盖的情况 | 核心断言 |
| --- | --- | --- |
| V7-E01 | 创建成功、服务器规范化名称、名称重复、缺失 / 无效新 ID | 使用真实 ID；不按同名认领；缺 ID 不生成假歌单或自动重建 |

| V7-E03 | 修改名称成功 / 拒绝 / 无变化 / 回查规范化，草稿保持 | 成功值来自服务端；失败保留草稿；无变化不请求 |

| V7-E06 | 添加弹层新建目标、创建完成、取消弹层、再次明确添加 | 创建与添加为两个意图；创建不自动写曲目；失败保留目标及必要草稿 |
| V7-T01 | 添加单曲 / 有界集合、输入重复、原已有部分 / 全部、非法 ID | 保留输入意图及去重结果；原已存在有准确反馈，全部存在不发送写请求 |
| V7-T02 | 移除单曲 / 有界集合、原不存在、歌单有重复 ID、资料缺失 | 按经核定的成员语义回查；不以展示行索引删错；缺资料保留 ID |
| V7-T03 | 部分写入、混合拒绝和未知、业务 code=512、响应无逐项结果 | 通过前后完整成员关系分类；总成功不能替代逐项状态；不复制 ID 自动重试或逆向补偿 |
| V7-T04 | ID 快照超 10,000 / 不完整、当前页仅 50 首、回查截断、跨页变更 | 不以分页 / 截断集合确认不存在；未满足完整性拒绝差集写入；提示明确 |
| V7-T05 | 增删后的计数、顺序、分页、选择、详情、多 Document 和播放队列 | 计数 / 详情取回读；相邻项选择有效；不重排或清空播放队列、不停止当前曲 |
| V7-D01 | 删除自有普通歌单、他人 / 内置 / 共享 / 未知歌单、权限中途变化 | 应用层独立拒绝非法目标；仅正确目标产生一个删除请求 |
| V7-D02 | 取消确认、默认焦点、按 Enter / Esc、确认后切换目标或账号 | 取消零写入；确认绑定目标和代次；陈旧确认失效，不能删新选中项 |
| V7-D03 | 明确成功、超时、已经不存在、403、目录部分读取、回查短时仍可见 | 区分已删除 / 明确拒绝 / 待核实；不可访问不等于删除成功；不会盲目再删 |
| V7-D04 | 双 Document 看同一歌单，另页看其他歌单，队列源自已删歌单 | 相关页面退回列表并清草稿；无关页面保持；队列保留且远端删除没有本地撤销入口 |

## 5. 并发、账号与资源寿命

| ID | 必须覆盖的情况 | 核心断言 |
| --- | --- | --- |
| V7-C01 | A 账号写入在途，退出后登录 B；相同账号重登但 Epoch 不同 | 所有旧成功、错误、事件、凭据提交和 UI 投递都不得污染新代次 |
| V7-C02 | 取消发生在发送前、发送期间、回执后、回查期间和 UI 排队后 | 发送前零写入；发送后不宣称远端撤销；迟到 UI 不提交；取消不变成自动重发 |
| V7-C03 | 老写操作 `finally` 晚于新账号操作；多页面同时请求 | 清理只释放本操作的闸门 / 忙碌资格；同代次最大并发写 1，不泄漏旧锁 |
| V7-C04 | 全量喜欢 / 目录 / 详情读取先开始后返回，跨过新写确认；连点刷新 | 旧 Revision 不覆盖新快照；必要时合并一次重读，不出现读写风暴 |
| V7-C05 | 关闭页面前未接受意图 / 已接受写入；最后一个 Document 关闭再开 | 未接受不发出，已接受由共享协调器完成有界收口；重开显示当前事实、声音继续 |
| V7-C06 | 插件 Shutdown、Standalone 释放、重复 Dispose、网络无响应 | 拒绝新操作、取消并有界结束尾任务，无死锁 / UI 等待环；先停库任务再释放登录等依赖 |
| V7-C07 | 服务端回执成功但 Cookie 持久化失败、回查失败；进程重启 | 保留远端已受理事实并显示待核实 / 存储问题；不重发；重启只重新读取，无持久写任务重放 |

回查预算另外以参数化测试覆盖：最多 3 轮、500 / 1,500 ms 等待、20 秒总窗口、15 秒单请求上限、每个等待点取消、429 / 验证 / 会话失效立即停止。该组方法至少映射到 L05、S05、E02、D03、C02 / C06 的对应路径，不能只验证一个计数常量。

```powershell

```

也可先单独运行门禁失败注入，再执行完整检查：

```powershell

pwsh -NoProfile -File tools/test-development-gate.ps1
pwsh -NoProfile -File tools/verify-development.ps1 -Milestone V7
```

| `v7-editor-{theme}-{width}.png` | 生产编辑表单和长文本校验反馈；3 尺寸 × 2 主题，舒适密度 | 6 张实际 PNG + 每张 `.json`；最窄表单可滚动到提交与取消 |
| `v7-delete-{theme}.png`、`v7-recheck-{theme}.png` | 删除确认、待核实 / 部分结果场景；800×600、双色 | 4 张实际 PNG + 每张 `.json`，目标及下一步可读 |

共 16 张 V7 专用截图；三尺寸双色两密度的完整组合另由布局测试覆盖，不要求所有 UI 状态做无意义的截图笛卡尔积。截图经真实渲染器生成并可解码，不能用空白图 / 复制图 / 手工 JSON 凑齐文件名。

每份 JSON 至少有 schemaVersion、provenance（runId、revision、sourceSha256），截图另有 name、width、height、sha256、realHost=false。检查文件时间属于本次测试窗口、字段类型和值域正确；`verification.json` 收录每个产物的实际字节数和 SHA256。计数必须来自 Fake 调用记录或实际控件观察，不写固定“预期值”当测量值。

冻结产物 schema 时保留场景级条目及操作关联：部分结果要求各分类合计等于输入唯一 ID 数，不能只判断一个 `passed=true`。本地 OperationId、合成 ID 可以记录，真实 Cookie、令牌及用户歌单内容不能进入自动证据。

## 9. 门禁自身的失败注入

| ID | 注入情况 | 必须得到的结果 |
| --- | --- | --- |
| V7-G01 | 子进程非零、超时、缺 TRX、TRX 损坏、失败 / 跳过 / 零测试 | 拒绝整次门禁，不继续输出通过报告 |
| V7-G02 | 缺任一必测场景、假方法、空映射、参数化数量不足、仅存在 Trait 无执行 | 拒绝；不能以总测试数或字符串匹配冒充覆盖 |
| V7-G03 | 缺产物 / 字段、错 schema / 身份 / 时间 / 哈希、损坏 PNG、错尺寸、缺一个布局组合 | 拒绝；复用旧 V6 / 旧 V7 产物不能通过 |
| V7-G04 | 写次数>1、旧账号应用>0、迟到覆盖>0、回查超预算、部分计数不守恒、残留订阅 / 媒体重开>0、错误字段类型 | 逐条拒绝；业务证据检查不能只检验文件存在 |
| V7-G05 | V7 分支漏掉 V6 或其他适用前置、链接无效、源码运行中改变、误启真实账号 / 发布字段 | 拒绝；新增版本不能绕过旧证据检查或把默认门禁变成发布 / 联网任务 |

每组有已知有效的正例，防止“所有情况都报错”也算自测成功。G05 应特别删除一个仅 V6 要求的产物 / 场景，再经 V7 路径检查，证明条件分支确实继承；仅单测 V7 检查函数不够。

门禁预算根据实际运行设置并记录，新增测试若超过旧超时应给出测量依据调整；不得吞异常、跳过用例或扩大业务请求预算来凑通过。

## 10. 真实账号与真实 Host 验收

自动测试通过后按实际环境执行以下项目。只使用用户明确指定用于验证的歌曲和歌单；删除只针对本次专门创建且已确认目标的测试歌单。真实写入由用户在 UI 中操作或明确授权的专用探针执行，不把人工步骤塞进常规门禁。先记录原状态，结束后逐项记录实际清理结果，不盲目补偿。

| ID | 人工步骤 | 完成依据 |
| --- | --- | --- |
| V7-H01 | 喜欢 / 取消指定歌曲；重新读取、重开 Document、官方客户端交叉核对 | 真实状态一致，搜索 / 歌单 / 队列 / 播放条同步；记录日期及账号条件概括，不记录凭据 |
| V7-H02 | 按 ID 打开未收藏歌单，收藏、重新读取、取消收藏；检查我的歌单 | 完整新收藏闭环和实际令牌 / 权限路径可用；结果与服务端一致 |
| V7-H03 | 新建测试歌单、改名、描述多行与清空、添加已有 / 新曲、移除、删除 | 每步写后读取；返回 ID、计数、内容、权限与确认目标一致；测试数据清理明确 |

| V7-H05 | 退出 / 重登后读取、正常关闭重开、可控制的失败提示复核和用户确认 | 旧状态不串账号、没有自动重放、待核实提示可理解；不能安全重现的真实竞态标未实测并引用自动覆盖 |

真实环境无法稳定制造超时 / 部分成功时，不对用户收藏反复破坏性试错；由可控自动测试证明分支，同时在记录中说明真实未重现的范围。人工记录不需要声称每种注入错误都在线重现。

Headless 不证明读屏 / 物理 IME / 声卡，Standalone 不证明真实 Host，HTTP 写回执不证明回查已完成；各自记录证据。没有真实账号条件时可以报告开发完成、人工待验，M3 验收状态继续保留未完成。
