## 1. 目标与首要规定

**目标：用户在已登录的插件里搜索歌曲，从结果中选中一首，实际播放，并能暂停、继续、停止、调节音量和查看进度。** 登录沿用现有成果。本方案保留设计与阶段验收标准，实际落地差异和进度见第 11 节；自动解码不代替真实扬声器与 Host 验收。

以下要求贯穿整个 V2 实施过程：

1. **SOLID 是首要规定。** 按变化原因分开账号会话、音乐 API、媒体取流、音频引擎、播放编排与界面投影；依赖方向、资源所有者和失败责任必须清楚。不得以赶通播放为由把网络、协议和音频控制堆进 ViewModel。
2. **设计模式朴素使用。** 使用普通类、不可变记录、枚举、构造注入和少量窄接口。仅在需要隔离网络、系统音频、文件、时间或 UI 调度的边界引入替换点，不引入通用播放器框架、事件总线、插件化协议平台或状态机库。
3. **注释使用详细中文。** 说明设计思路、协议依据、线程与取消约定、数据和资源寿命、失败后的状态；公开契约写明输入、输出、异常和调用限制，不逐行翻译代码。
4. **单元测试与本地开发门禁齐全。** 专用矩阵覆盖正常路径、失败、竞态、资源释放及登录回归；门禁校验实际测试结果，不只看命令退出码。真实音频输出与 Host 联调单独留证。
5. **实现与文档同步。** 本方案维护阶段进度，专用矩阵维护测试映射；实际协议、操作步骤和当次验证证据各归其位，不把规划写成现行能力。
6. **不使用 AIFLOW，不新增或运行 Windows CI、发布门禁。** 不执行发布 Smoke、seal、发布覆盖率、发布重复性检查或正式 ZIP 发布。Windows 本机 Debug 验证和真实 Host 开发联调属于本阶段；发布时再使用发布门禁。
7. **播放库必须具备跨平台能力，播放器由插件内部承载。** 首选 LibVLCSharp + LibVLC，目标覆盖 Windows、Linux、macOS；界面、播放编排及引擎适配均在 Plugin，Standalone 与 Tests 复用。当前先在 Windows x64 完成 M1，其他系统按第 3.4 节逐项验证，不能把 Windows 通过写成全平台完成。
8. **保留既有接入边界，允许共用运行库目录。** 插件主动 HTTP 统一使用 Flurl；通过公开 SDK 接入 Host，不引用 Host 内部工程。引擎在 Host 进程内运行；优先使用有效内置 LibVLC，其次使用用户指定目录，不强制每个插件自带一份原生库。

## 2. M1 范围与完成条件

| 能力 | V2 交付范围 | 本阶段行为 |

| 歌曲搜索 | 歌名/歌手关键词、歌曲类型、分页、加载、空结果、失败重试 | 已登录后使用；提交按钮或回车搜索，默认每页 30 条；新搜索替换旧结果 |
| 歌曲详情 | ID、名称、歌手、专辑、封面、时长 | 搜索摘要可先展示；按选中歌曲补取详情，封面失败使用占位图 |

| 单曲播放 | 加载、播放、暂停、继续、停止、自然结束、音量 | 一个插件容器最多一个活动音源；选另一首会替换当前单曲，不形成队列 |
| 播放信息 | 当前歌曲、当前时间、可播放时长、状态和失败提示 | 进度只读；试听明确标记，整曲元数据时长不冒充实际可播时长 |
| Document | 账号摘要、歌曲搜索结果、单曲控制与既有登录入口 | 保留微信/App 登录、恢复、重试保存与退出；按钮有效性与状态一致 |
| 账号与设置 Tool | 登录信息、LibVLC 目录设置、检测与生效状态 | 插件级单例；未登录也能配置，隐藏 Tool 不停止播放或清除设置 |
| LibVLC 来源 | 有效内置目录优先，其次用户指定的本地运行库目录 | 可显式指向多个插件共用的目录；不共享播放器对象或账号状态 |
| 生命周期 | 切歌、停止、页面关闭、退出账号、Host 停止 | 取消请求、拒绝迟到结果、停止音源并释放资源，规则见第 6 节 |

歌单、队列、上一首/下一首、循环/随机、进度拖动、歌词、喜欢、下载任务、最近播放持久化、系统媒体控制及跨页面后台连续播放归后续里程碑。V2 不自动上报听歌记录，不增加跨插件工作台命令或 Workflow Action。

完成 M1 必须同时满足：

- 一首真实账号可播歌曲完成“搜索 → 选中 → 资源解析 → 实际出声”，暂停、继续、停止和音量有效。
- 快速切换 A/B 时仅最新选择生效，无双重播放；停止或退出后旧响应不能再次启动音频。
- 无地址、试听、格式不支持、设备不可用和网络失败都有明确结果，单曲失败不误判整个账号失效。
- 新增自动测试和既有登录回归通过；Standalone 与真实 Host 的音频和关闭行为分别验证。
- Windows x64 分别验证内置库和“无内置库 + 指定目录”播放；Tool 显示实际来源，路径变更生效规则明确，与现有视频插件共用运行库及各自内置库均有共存证据。
- Document 停靠/浮动/切换及 Tool 隐藏/重开不会误停、重播或重复订阅；真正关闭播放所有者仍按第 6 节停止。
- 当前契约、快速开始、专用矩阵、导航与当次实施记录同步更新，未覆盖事项明确保留。

### 3.2 音频引擎与媒体输入决策

**首选方案调整为 LibVLCSharp + LibVLC。** LibVLCSharp 是 C# 调用层，LibVLC 是实际负责解码和输出的原生引擎；官方支持 Windows、Linux、macOS。这取代初版的 NAudio / Windows 输出验证方向，具体稳定版本及平台原生资产在 S0 验证后锁定。[LibVLCSharp 官方项目](https://github.com/videolan/libvlcsharp)

音乐插件使用核心包 `LibVLCSharp`，由拟建的 `LibVlcAudioOutput` 封装 `LibVLC`、`Media`、`MediaPlayer`。播放按钮、音量和进度使用现有 Avalonia 控件，不引入视频窗口，也不需要 `LibVLCSharp.Avalonia` 的视频视图适配。业务和页面只依赖 `IAudioOutput` 等应用契约。

**M1 首选有界临时文件方案：Flurl 下载当前单曲 → 完成校验 → 引擎读取本地文件 → 系统输出。** 这样能保持 HTTP 所有权统一，并先把取消、文件和解码寿命做完整。等待下载期间显示“正在加载”，不承诺边下边播；该延迟取舍须在真实歌曲样本中观察。

S0 必须给出：所选包和框架兼容性、至少一种真实返回格式的可用解码链、暂停/继续/停止/音量结果、原生资产清单及来源、内置/指定目录加载与 Host 共存结果、加载耗时与支持范围。MP3/WAV 受控样本成功不能外推所有网易音频都可播。依赖版本以锁定包为准，不照抄某一历史大版本的 API 名称。

如果首选引擎或输入方式不满足实际格式、跨平台或插件内承载要求，先记录原因，再替换该适配边界；替代库仍须满足这些要求，不通过引擎自行联网绕过 Flurl 约定。`song_url` 仅保留为有证据的协议替代候选，未经实测不静默降级或将“搜索可用”标记为 M1 完成。

### 3.3 内置优先、指定目录与多个插件共存

**“插件内部”约束界面和执行：** 音乐控件由插件提供，引擎在 Host 进程内运行，不启动外部 VLC 播放器。原生库既可以随插件携带，也可以来自用户指定的公共目录；自包含交付不再是必选项。

首次原生初始化前使用以下固定顺序：

1. 无副作用检查以插件程序集为基准的 `native/<rid>/libvlc/`；文件、架构和所需模块有效时优先选用。
2. 内置不存在或检查不通过时，检查已保存的用户目录；它可指向公共 LibVLC 安装目录，也可显式指向 VideoSecurityPlayer 使用的原生目录。后者只复用文件，不引用视频插件程序集。
3. 两者都不可用时，保持登录、搜索和 Tool 可用，禁用播放并给出具体检测结果；不扫描其他插件、PATH 或任意系统目录。

Tool 同时显示“配置目录”“下次初始化候选来源”和“本进程实际使用来源/路径”；内置优先时明确提示配置目录暂未采用。目录检查失败可以修正后重检；一旦尝试原生初始化，不再在同一进程盲目改路径重试。保存不同配置后提示重启 Host 生效，当前播放使用原快照，不能热卸载 DLL。

多个插件可以加载同一组兼容的库文件，各自拥有 LibVLC/MediaPlayer 和状态；不为此新增跨插件全局播放服务。共享目录只读使用，音乐插件不负责覆盖、升级或删除其中的库。不同版本或加载顺序的冲突须有明确失败结果；托管隔离不能证明原生完全隔离。完整选择表、设置契约和共存场景见[专项设计](netease-v2-libvlc-tool-and-dock-design.md)。

邻近视频插件的当前实现仍固定使用自身原生目录，没有用户指定路径功能；参考其探针、初始化顺序及资源所有权，不把本次新增需求写成它已经具备的能力。

### 3.4 跨平台边界

Windows x64 首先验证内置和指定目录两条路径。Linux x64 需明确发行版/ABI 并验证目录内动态库依赖和模块发现；macOS arm64/x64 需分别验证架构和动态库布局。库、模块和必要配套依赖必须匹配，单个主库文件不构成可用运行时。

特别是 Linux，当前官方 `Core.Initialize` 文档说明其目录参数不受支持，另指向 `LD_LIBRARY_PATH`。[官方 API 说明](https://docs.videolan.me/libvlcsharp/api/LibVLCSharp.Shared.Core.html) 因此指定目录功能也必须有对应平台的实际加载验证，不能直接照搬 Windows；不通过修改 Host 全局环境掩盖插件之间的依赖问题。

**播放引擎跨平台与整个插件跨平台分别跟踪。** 当前 [会话保护](../../src/MusicNetEasePlugin.Plugin/Infrastructure/Persistence/SessionProtection.cs)仅实现 Windows DPAPI，构建固定为 `win-x64`。后续还需受保护存储、Host/SDK 和按 RID 构建适配。Windows M1 可以单独验收；其他平台只在相应加载、输出、登录/会话及 Host 验证完成后标为已支持。

## 4. SOLID 分工与设计思路

以下名称为拟定名称，实现时可按仓库风格微调，但职责和依赖方向应保持。

| 组件 | 唯一主要职责 | 设计理由与所有者 |
| --- | --- | --- |
| 已提交账号会话对象 / `IMusicSessionAccessor` | 提供受控请求快照、撤销信号与同代次响应提交 | 登录编排和音乐请求共用一份已提交会话；容器拥有，UI 不读取它 |
| `IMusicCatalogApi` | 搜索、详情的类型化请求与结果转换 | 与播放引擎无关，不增加到 `INeteaseAuthApi` 中 |
| `IPlaybackResourceResolver` | 为歌曲解析播放资源和不可播/试听结果 | 播放资源协议可独立变化，不要求搜索接口知道媒体流 |
| `NeteaseTransport` 与协议编码器 | Flurl 请求、有限读取、公共失败信息与加解密 | 复用并渐进调整；端点业务含义留给相应 API |
| `IMediaBuffer` | Flurl 媒体获取、有界临时文件及清理 | 不启动音频；返回具备明确释放责任的媒体资源 |
| `IAudioOutput` / `LibVlcAudioOutput` | 本地媒体打开、输出、暂停、继续、停止、音量与进度事件 | LibVLCSharp 类型留在 Infrastructure；与 Cookie、网易 API、Avalonia 分离 |
| `LibVlcRuntimeResolver` / 运行库探针 | 按内置优先规则生成带来源的候选快照，检查目录、架构与模块 | 检查不加载原生库，选择与初始化分开，复用普通记录和具体类 |
| `ILibVlcSettingsStore` | 保存本机指定目录及配置版本 | 文件边界可替换；独立于账号凭据存储，不在设置中保存 Cookie |
| `LibVlcRuntime` | 按冻结的候选初始化并管理容器使用的 LibVLC 实例 | 每个插件容器惰性复用一个引擎实例，记录有效路径；不随每首歌或 Dock View 重建 |
| `PlaybackCoordinator` | 单曲播放状态、操作顺序、切歌代次、错误和资源所有权转移 | 容器内一个实例，使用普通方法和枚举；不自己实现 HTTP 或解码 |
| 搜索页面模型、播放区模型 | 局部命令、结果展示、订阅与 UI 调度 | 每个 Document 拥有；只消费应用结果，不直接触碰磁盘或音频库 |
| `MusicSettingsTool` / `MusicSettingsView` | 账号摘要、目录草稿、检测/保存结果和登录入口 | 模型为插件级单例，View 可重建；消费共享状态，不拥有或释放播放器 |
| `MainDocument` 与插件 Lifecycle | 页面组合、Document 所有者信号、Host 启停 | MainDocument 保持轻薄；Lifecycle 明确先停止任务、再释放依赖 |

SOLID 的审查要求：

- **单一职责：** 修改搜索协议无需改音频输出，替换引擎无需改登录 UI；实际代码据此分组。
- **开闭原则：** 不为未来 440 个接口预建框架；新增需要只扩展相应窄适配，稳定用例无需识别具体实现类型。
- **里氏替换：** 真引擎与测试替身遵守同一状态、取消、异常、事件和释放契约，不能靠假实现省略困难路径。
- **接口隔离：** 搜索只依赖目录查询，播放器只依赖资源、媒体与音频；只需两个操作的调用方不接收“万能网易服务”。
- **依赖倒置：** Application 定义需求，Infrastructure 实现端口，唯一服务注册入口组装；不从业务类解析 DI 容器。

建议沿用现有目录增加 `Application/Music`、`Application/Playback`、`Infrastructure/Audio` 与 `Infrastructure/Media`。网络适配继续在 `Infrastructure/Http`，页面在 `Features`。不额外拆公共 NuGet 包或建立第二套 Standalone 实现。

## 5. 会话、错误与数据约定

### 5.1 已登录会话访问

1. 登录候选会话仍由登录尝试拥有；只有账号核验并提交后，音乐业务才能获得不可变请求快照。保存失败但内存登录有效的账号仍可播放。
2. 请求携带账号代次、凭据版本和取消信号。账号代次在退出/新会话时变更，同一账号重新登录也视为新代次；不复用登录 UI 的 `Revision` 作为账号身份。
3. 会话失效或退出立即撤销音乐请求资格，清除搜索/播放投影并停止输出；网络取消不能取消本地清理责任。
4. 迟到响应只有在同账号代次、适用凭据版本时才能提交 Cookie/协议状态。冲突响应不覆盖新凭据；必要的受保护保存由会话所有者统一负责，沿用保存失败反馈。
5. 网络、磁盘和音频 await 不持有状态锁；取消回调、事件通知和跨组件调用放在锁外。调整登录提交逻辑时完整回归原有保存、取消补偿与退出行为。

### 5.2 结果与错误

歌曲模型只承载业务展示数据；资源模型仅由播放链持有临时 URL、格式、实际音质、有效信息和试听范围，不进入日志、ViewModel 或持久化队列。

| 分类 | 用户行为 |
| --- | --- |
| 搜索空结果 | 显示空状态，不作为网络错误 |
| 无播放地址 / 明确受限 | 显示暂不可播放或服务端有依据的具体原因，保留账号状态 |
| 试听 | 显示试听标记并按实际范围播放，不把试听结束记为播放故障 |
| 登录确实失效 | 撤销对应账号代次的音乐操作，提示重新登录；不因媒体 CDN 的 403 直接退出账号 |
| 限流 / 额外验证 | 停止本次自动流程，保留可操作提示，不高速重试或自动重登 |
| 网络、超时、无设备、解码失败 | 释放本次资源，显示可重试失败；不伪装为正在播放 |
| 用户取消 / 切换 / 正常停止 | 正常收口，不弹出失败提示 |

音乐 API 失败使用独立业务错误分类；公共传输层保留必要 HTTP 状态、业务码、Retry-After 和失败阶段，不向上泄露原始正文、Cookie、协议密钥或完整资源 URL。既有登录适配继续提供原有 `AuthException` 契约。

### 5.3 请求与临时媒体策略

下面是 **M1 建议初始配置**，不是网易限制或既有实现；S0 用实际样本校准后记录最终值。

| 项目 | 初始策略 |
| --- | --- |
| 搜索与详情 | 单次 15 秒、JSON 上限 1 MiB；一页 30 条，不无限累计全部结果 |
| 媒体请求 | 独立 Client，无账号 Cookie/CSRF；只接受经校验的来源与协议，重定向逐跳核对且最多 3 次 |
| 媒体读取 | 响应头和读取空闲预算各 15 秒，总预算 120 秒；实际已读字节上限 64 MiB，不能只信 Content-Length |
| 临时文件 | 插件数据目录下按实例/操作生成唯一名称；校验完成前为未完成文件，引擎不读取半成品 |
| 失败重试 | 普通网络失败由用户重试；明确为地址过期且尚未输出时，最多重新解析 1 次，不对所有 403 盲目重试 |
| 正常清理 | 替换、停止、结束、失败、页面所有者关闭或退出时，停止输出、解绑并释放本次 Media/文件句柄，再删除临时文件；共享引擎只在容器结束时释放 |
| 异常残留 | 使用实例占用标识，后续启动只清理可确认无活动所有者的插件自有残留；路径必须在专属目录内，不清扫通用 Temp 或其他实例 |

不按 URL 扩展名或 Content-Type 单独认定格式；检查实际媒体和解码结果，拒绝错误页、截断数据和异常大小。文件删除失败须可诊断并留待受控清理，不能在持有文件句柄时反复删除。M1 不承诺断点续传、离线曲库或保留下载文件。

## 6. 播放状态、竞态与页面行为

| 当前状态 | 可用操作 | 结果 |
| --- | --- | --- |
| Idle / Stopped / Ended / Failed | 从结果选择播放；可重试当前歌曲 | 创建新操作，重新取得有效资源 |
| Loading | 停止；改选另一首 | 取消旧解析/下载/打开，清理后只保留最新操作；暂停不可用 |
| Playing | 暂停、停止、调音量、改选歌曲 | 暂停保留当前媒体位置，停止释放本次媒体 |
| Paused | 继续、停止、调音量、改选歌曲 | 继续当前媒体；停止后不承诺可直接复用旧 URL |
| 音频自然结束 | 再次播放或选择别的歌曲 | 进入 Ended 并释放媒体，不自动播放下一首 |

“Playing”由引擎确认输出运行后发布，调用 Play 方法成功返回不自动等同用户已听到声音。进度以引擎时间为准，通知节流且切回 UI 线程；音量 0 仍是播放状态，不能用静音推断引擎失败。

每次选歌登记新的播放操作代次，取消并等待旧操作完成清理后再接管引擎。解析、下载、音频事件和 UI 投影均检查代次；快速 A → B → C 只允许 C 最终接管，已失效的 B 不继续排队出声。停止等控制操作也按顺序处理，避免暂停完成回调覆盖更新后的停止状态。

**M1 页面关闭约定：** 播放尝试与音频归属最近一次发起播放的 Document。该 Document 真正关闭时停止其播放；其他页面关闭不能停止它。临时移出视觉树、切换 Dock 可见性不等于 Document 关闭。多页面共享一个播放器状态；不创建各自的音频引擎。跨页面关闭后继续后台听歌留给 M2。

退出账号先撤销资格、取消音乐工作并立即请求停止音频，再收口会话清理；即使远端退出失败，也不继续播放。Host 停止统一撤销入口，等待搜索、播放和登录工作收口，再释放媒体、引擎及 Flurl Client。同步 Dispose 路径不得等待必须回到 UI 线程的 continuation。

页面布局维持一个 Document：账号区展示连接状态，主体为搜索框及分页结果，播放区展示单曲和控制。加载与错误按区域呈现；保留编译绑定、合理的最小窗口布局和占位图，不暴露 xeapi、临时路径等实现细节。

### 6.1 账号与设置 Tool

增加“网易云音乐 · 账号与播放设置”Tool，拟定稳定 ID 为 `myavalonia.plugin.music.netease.tool.account-settings`，默认右侧，关闭行为采用 SDK 的 `ToolCloseBehavior.Hide`。通过 `AddTool<MusicSettingsTool, MusicSettingsView>` 注册，Host 持有单例模型，不能重复手工登记根模型生命周期。

Tool 展示昵称/账号标识、登录和保存状态，提供恢复、重试保存与明确的退出操作；微信/App 二维码继续复用原有 Document。实施核对 SDK 3.4.1 没有运行时打开指定 Document 的公开端口，因此 Tool 提示从“新建”打开网易云音乐，不引用 Host 内部服务。设置区包含 LibVLC 目录输入/选择、检测、保存、清空配置，以及候选/实际来源和重启待生效提示。账号未登录或库缺失时仍能打开 Tool。

路径设置保存在插件数据目录的独立配置文件，只保存目录和 schema 版本；退出账号不删除它，修改它不触碰受保护会话。草稿、检测结果、已保存值、当前生效值分开，保存失败不冒充生效。Tool 隐藏或浮动重挂仅影响 View，模型和已保存设置保持；不取消 Document 的登录尝试或播放。

### 6.2 Dock 与原生生命周期约定

- Document 真正关闭以 `IDocumentLifetime` 为准；切换标签、停靠/浮动、重新挂载 View 不能调用播放 Stop/Dispose，也不能重发 Play。重建 View 读取当前快照，不重新开始歌曲。
- View 更换 DataContext 或 detach 时退订自己持有的事件，清理本地定时器和选择器请求；重新 attach 的订阅幂等，迟到回调检查 View/请求代次。不能在 View 消失时 Dispose 注入的单例 Tool 或共享服务。
- LibVLC 初始化及可能阻塞的 Play、暂停、Stop、Media 解绑和释放在受控的后台串行路径完成；不能靠并行 Task.Run 打散顺序，也不能在原生回调中同步等待 Stop/Dispose。UI 只异步接收投影。
- 音频无需 HWND/VideoView，故不复制视频插件的“丢失表面 → Stop → 重建句柄 → Seek 恢复”流程。保留其取消、代次和资源所有权经验，不引入视频状态机。
- 文件夹选择留在 View，使用当前 TopLevel 的 StorageProvider；防重入，返回时检查原 ViewModel、当前挂载和请求代次，旧窗口选择结果不得覆盖新设置。

VideoSecurityPlayer 的现行代码与历史文档有演进差异；已核对的具体问题、证据及本插件采用方式集中在[专项设计第 5 节](netease-v2-libvlc-tool-and-dock-design.md#5-videosecurityplayer-的-dock-与资源经验)。
