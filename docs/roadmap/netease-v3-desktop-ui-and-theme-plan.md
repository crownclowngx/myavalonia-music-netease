# 网易云音乐 V3：Document / Tool 紧凑桌面布局、深浅主题与轻量动效改造方案

> 对象：仅 `MusicNetEasePlugin` 的音乐 Document、账号与播放设置 Tool，以及复用它们的 Standalone。
> 状态：V3 核心实现及本地自动验证完成；真实 Host/Dock、系统主题联动、缩放与硬件性能验收待完成。实施状态见第 10 节。
> 创建日期：2026-09-23。调研基线：`3018bb30ea6152fa4f7addf312540aad99df395e`；编写前本插件工作树干净。
> 编号：承接 V1 登录、V2 搜索与单曲播放，采用 **V3**；属于改造序号，不修改插件包、SDK 或能力里程碑编号。
> 关联：[当前播放契约](../reference/netease-music-playback.md) · [V2 运行库、Tool 与 Dock 设计](netease-v2-libvlc-tool-and-dock-design.md) · [能力路线图](netease-capability-roadmap.md)。

**本轮目标：把音乐 Document 改成紧凑、现代的桌面播放器，把 Tool 改成紧凑的属性设置面板，两者随 Host 的深色、浅色主题即时切换，并用少量短动画反馈交互。** 现代感来自清晰层次、统一密度和及时反馈；动效必须具有明确用途，并在静止或隐藏时停止消耗装饰性渲染资源。

## 1. 现状判断：浅色背景在哪里，“像手机”从哪里来

### 1.1 改造前源码事实（基线 3018bb3）

以下描述改造前问题，链接指向当前文件便于对照；现行行为以[当前界面契约](../reference/netease-desktop-ui.md)为准。

| 位置 | 当前实现 | 影响与改造判断 |
| --- | --- | --- |
| [MainView.axaml](../../src/MusicNetEasePlugin.Plugin/Features/Main/MainView.axaml) | 根 `ScrollViewer Background="#F5F6F8"`；账号卡片和包住 `MusicView` 的卡片均为 `Background="White"` | **确实存在公共的浅色外层，但它在本插件 Document 内。** 即使内部控件跟随深色主题，外层仍是浅色 |
| 同一 MainView | `Margin="32"`、`MaxWidth="820"`、水平居中；卡片圆角 16、内边距 24–28；标题字号 28 | 宽工作区仍显示居中窄栏，账号区占据首屏，内容像手机登录页或网页卡片 |
| 同一 MainView | 正文、说明、状态文字分别固定为 `#17202E`、`#667085`、`#344054` 等 | 只替换背景会留下深色文字；必须成组处理背景、文字、边框和状态色 |
| [MusicView.axaml](../../src/MusicNetEasePlugin.Plugin/Features/Music/MusicView.axaml) | 整体 `StackPanel`；搜索结果固定高 260；每首歌三行；封面、歌名、专辑、进度、按钮、音量继续纵向排列 | 高窗口没有用于增加结果区域；主要播放操作可能落到外层滚动区域下方 |
| 同一 MusicView | 试听文字固定 `#B54708`，封面占位底色固定 `#18777777` | 深色下的状态对比度与占位层次需要单独处理 |
| [MusicSettingsView.axaml](../../src/MusicNetEasePlugin.Plugin/Features/Settings/MusicSettingsView.axaml) | `ScrollViewer + StackPanel`，边距 16、间距 12、标题字号 20，多组 `WrapPanel` 按钮和长路径文字 | **没有发现与 Document 相同的白色根背景。** Tool 主要需要紧凑分区、操作分组和宽度适配，不能套用同一个根因 |
| [Standalone App](../../src/MusicNetEasePlugin.Standalone/App.axaml) | 仅加载 `FluentTheme`，没有插件双色资源 | 当前预览不能证明插件已经正确处理自定义背景和状态色 |

在本插件生产源码中未发现强制 `RequestedThemeVariant="Light"` 或设置全局主题的代码。固定颜色不会阻止主题传播，但会让对应区域的颜色不随主题变化；部分默认控件变深、外层仍浅时，还会形成混搭。

作为只读核对，Host 的 [App.axaml](../../../../avalonia_dock_simple_test/Host/MyAvaloniaManagement/App.axaml) 已有 Light / Dark 资源和 Dock 双色预设，[ApplicationThemeService](../../../../avalonia_dock_simple_test/Host/MyAvaloniaManagement/Business/Appearance/ApplicationThemeService.cs) 会设置应用主题。本轮有充分依据先修插件自身；尚未用当前部署产物做运行时截图与资源来源检查，不能宣称排除了所有 Host 或部署因素。

### 1.2 改造优先级

1. **P0：修复颜色链。** 先清除 Document 的固定浅色外层和固定正文色，补齐 Document、Music、Tool 的双色语义资源。
2. **P1：重排 Document。** 搜索结果占据主体；账号摘要、搜索、分页和播放控制有明确位置，播放条不随结果滚走。
3. **P1：整理 Tool。** 账号、目录编辑、检测与保存、实际运行状态分区；窄停靠和底部停靠都能操作。
4. **P1：轻量动效。** 悬停、选中、局部状态切换有短反馈；不增加持续播放的装饰动画，并提供减少动态效果选项。
5. **P2：补齐预览和验证。** 覆盖主题热切换、窄尺寸、浮动与回停、位图释放、动效开销和既有 M1 生命周期。

## 2. 范围与实现约束

- 改动集中于本插件的 `Features/Main`、`Features/Music`、`Features/Settings`、局部样式资源、Standalone 和相关 UI 测试。
- 保留 `myavalonia.plugin.music.netease.document.main` 与 `myavalonia.plugin.music.netease.tool.account-settings` 身份、既有注册和默认右侧 Tool；布局更新继续识别已保存的 Dock 项目。
- 继续使用现有登录、搜索、分页、单曲播放、暂停、继续、停止、音量和 LibVLC 设置能力。歌单、队列、歌词、上一首/下一首、进度拖动及关闭页面后连续播放仍归后续能力里程碑；本轮界面不放置这些未实现的操作。
- 保持 SOLID 分工，样式和尺寸行为归 View，业务状态由现有模型投影；确有需要时增加少量只读显示属性。代码注释用中文说明主题来源、控件重挂和资源所有权。
- 使用普通资源字典、局部样式和明确布局，避免为一个插件建立公共 UI 框架、主题服务或新的事件总线。不修改 Host、其他插件、SDK 或全局控件主题。
- 延续本仓本地开发方式，不使用 AIFLOW、Windows CI 或发布门禁。方案编写不执行部署；后续开发验证、实机验收、部署各自留证。

## 3. Document：从纵向卡片页改为桌面音乐工作区

### 3.1 已登录布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 网易云音乐                         小头像  昵称 · 已连接  [账号 ▾]    │
├──────────────────────────────────────────────────────────────────────┤
│ [搜索歌名或歌手________________________________________] [搜索]       │
│ 按需出现：加载、搜索错误、会话保存失败及对应恢复操作                   │
├──────────────────────────────────────────────────────────────────────┤
│ 歌曲                         歌手              专辑            时长   │
│ 歌曲 A                       歌手 A            专辑 A          03:42  │
│ 歌曲 B                       歌手 B            专辑 B          04:10  │
│ …                     结果区域随工作区增高而增长                     │
├──────────────────────────────────────────────────────────────────────┤
│ [播放所选]                              [上一页]  第 1 页  [下一页]   │
├──────────────────────────────────────────────────────────────────────┤
│ 封面  当前歌曲 / 歌手       [暂停或继续] [停止]       音量 ─── 70      │
│       状态 / 试听          ━━━━━只读进度━━━━━       00:35 / 03:42      │
└──────────────────────────────────────────────────────────────────────┘
```

这是布局示意；歌曲信息与播放状态全部使用真实数据。上方“播放所选”操作结果列表的选中项，下方播放条显示实际播放快照，两者不混用。

具体规则：

1. 根布局使用 `Grid` 的 `Auto / * / Auto` 区域组织内容；移除覆盖整个 Document 的外层滚动和 `MaxWidth=820`。只让结果列表、长错误详情或登录内容的必要区域滚动。
2. 已登录时，账号缩为约 36–40 DIP 高的摘要行；去除欢迎式副标题、大头像和常驻“账号已连接”卡片。账号菜单保留既有恢复、重试保存、退出/清理入口，失败时把恢复动作直接放到提示旁。
3. 音乐结果使用现有 `ListBox` 配合行内 `Grid` 与一致列宽；首轮不为外观引入新的 DataGrid 依赖。保留虚拟化与受约束的可视高度，取消固定 260 高度和三层外部滚动。
4. 宽布局展示歌曲、歌手、专辑、时长，时长取已有 `MusicTrack.DurationMs`；未知值显示占位。列头先作为说明，不表现成尚未实现的排序按钮。
5. 单击仅选择，显式“播放所选”开始播放。搜索框回车沿用现有搜索命令；如增加列表双击播放，也必须复用同一个 `PlayCommand` 并验证命中项和禁用状态。
6. 播放条位于音乐区底部，宽布局建议 88–112 DIP；封面约 44–48 DIP，不单独占据一整行。暂停/继续按真实状态切换显示，加载、失败、试听和停止状态都有文字反馈。
7. 进度保持只读，不换成可拖动 Slider；音量继续为可编辑 Slider。长歌名与专辑省略，完整信息可通过提示或可复制详情访问。
8. 不把账号成功信息、搜索结果和播放错误合成一个通用状态文本。提示出现在对应区域，详细错误可展开，避免大块提示把列表和播放控制挤出可见区域。

### 3.2 未登录与恢复状态

登录仍属于同一个 Document。未登录时，主体替换为紧凑登录区：宽布局左侧放二维码，右侧放登录方式、扫码说明、状态与操作；不保留空结果表和不可用播放按钮占据首屏。

- 微信扫码为默认入口，网易云 App 为备用入口；取消只在对应流程有效时呈现，重试恢复、保存失败重试和本地清理提示继续可达。
- 二维码显示区建议 200–224 DIP，并保留完整静区；实际渲染必须验证识别效果，不能裁剪图像或为了密度压成小图标。
- 登录后主体切换到歌曲列表，保留已有账号、请求代次、恢复及取消语义。展开账号信息不是退出登录，也不重建播放器。
- 长说明置于较低层级或帮助提示；失败和清理未完成状态保持直接可见。

## 4. Tool：紧凑的账号与播放设置面板

Tool 服务于账号管理与环境设置，不承担第二套播放器或登录页。Dock 标题已经说明用途，正文取消重复的大号“账号与播放设置”标题。

```text
┌ 账号 ─────────────────────────┐
│ 昵称 · 账号标识               │
│ 登录/保存状态及必要提示       │
│ [恢复登录] [重试保存] [更多 ▾]│
├ 播放运行库 ───────────────────┤
│ 自定义目录（内置库优先）      │
│ [目录草稿________________] […]│
│ [检测目录] [保存配置]         │
│ 检测结果 / 保存结果           │
├ 实际状态 ─────────────────────┤
│ 已保存配置：…                 │
│ 下次候选：内置 / 配置 / 不可用│
│ 当前加载：来源、版本、路径    │
│ 待重启生效提示（如适用）      │
│ [刷新状态] [清空配置]         │
├ 界面 ─────────────────────────┤
│ [ ] 减少动态效果              │
└───────────────────────────────┘
```

1. 默认按“账号 / 播放运行库 / 实际状态”三段展开，使用细分隔线和 6–8 DIP 间距；详细诊断可以折叠，检测失败和待重启提示不能被默认隐藏。
2. 退出账号属于账号操作，可放入有文字说明的更多菜单；它仍复用 `LogoutCommand`。重试保存只有适用时突出展示，不把所有按钮都做成主操作。
3. 目录输入与选择按钮占同一行；长路径允许输入框内水平滚动。只读完整路径使用可选择文本并允许换行，不撑宽整个 Tool。
4. 明确区分 `DirectoryPath` 草稿、`SavedDirectory` 已保存值、`CandidateRuntime` 候选与 `ActiveRuntime` 当前加载。不能因保存成功就显示“已经切换运行库”。
5. “检测目录”只检查；“保存配置”才提交；“清空配置”只移除配置值，不删除目录。内置优先、加载后待重启的现有规则不变。
6. 未登录也能使用运行库设置。扫码仍提示从 Host“新建”打开网易云音乐；当前 SDK 3.4.1 没有 Tool 主动打开指定 Document 的公开运行时端口，不新增无效跳转按钮或引用 Host 内部服务。
7. 窄 Tool 使用明确的两行按钮布局，避免让一串长按钮随宽度随机换行。底部停靠且宽度充足时可将账号与运行库区并排；高度不足时内容区域滚动，所有操作保持可达。
8. 若需要把当前组合字符串拆为“来源 / 版本 / 路径 / 是否待重启”，从现有状态对象增加只读投影；不得解析中文提示字符串推断状态，或在 View 中再探测一次运行库。

## 5. 主题：插件局部的完整双色资源

### 5.1 资源组织与作用域

已新增 `src/MusicNetEasePlugin.Plugin/Styles/NeteaseThemeResources.axaml` 和 `NeteaseControlStyles.axaml`，分别承载语义画刷与 `netease-*` 类样式。三个生产 View 使用同一份资源源文件，资源包含在 Plugin 内，Standalone 与 Tests 复用生产 View 即可获得相同资源。

- 在 View 局部合并资源，使用 `ResourceDictionary.ThemeDictionaries` 分别定义 Light 和 Dark。插件不修改 `Application.Current.Resources`、Host 的 `App*` 键或全局 `Button` / `TextBox` 样式。
- Document / Tool 不主动选择主题，从所在窗口和 Host 继承。Standalone 仅在预览入口提供“跟随系统 / 浅色 / 深色”切换，不另存一套插件主题偏好。
- 颜色、画刷使用 `DynamicResource`；插件专用键统一用 `Netease` 前缀，不依赖 Host 未公开的 Dock、Semi 或 Ursa 内部资源名。标准输入、按钮、菜单沿用宿主控件主题，仅以局部类调整密度和必要状态。
- 移除 View 属性上的旧颜色常量与冲突 Setter；不能只新增字典而保留 `Background="White"`。资源应成对覆盖背景和前景，检查悬停、选中、焦点、禁用及菜单打开状态。

Avalonia 官方说明支持以主题字典和动态资源响应主题变化；靠近控件的同名资源可能覆盖更高层资源，定位时需要检查具体来源。参见[主题变体](https://docs.avaloniaui.net/docs/styling/theme-variants)与[资源查找](https://docs.avaloniaui.net/docs/app-development/resources)。

### 5.2 建议的最小颜色集合

以下设计初值已进入局部资源字典；真实 Host 实机效果仍需校准。标准控件模板内部可能继续使用所在控件主题的画刷。

| 语义键 | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `NeteaseDocumentBackgroundBrush` | `#FFFFFF` | `#1E1E1E` | Document 主体底色 |
| `NeteaseToolBackgroundBrush` | `#F5F5F5` | `#252525` | Tool 底色 |
| `NeteasePanelBrush` | `#F3F4F6` | `#2B2B2B` | 播放条、局部信息区与封面占位 |
| `NeteaseTextBrush` | `#202020` | `#F0F0F0` | 正文、歌曲与路径 |
| `NeteaseSecondaryTextBrush` | `#666666` | `#B8B8B8` | 次要信息，避免再叠低透明度 |
| `NeteaseAccentBrush` | `#C92B42` | `#FF7185` | 少量音乐品牌强调、局部活动标记；不替代错误状态色 |
| `NeteaseBorderBrush` | `#D5D7DA` | `#454545` | 分区、输入外框和分隔 |
| `NeteaseHoverBrush` | `#EBEDF0` | `#333333` | 列表悬停 |
| `NeteaseSelectionBrush` / `NeteaseSelectionTextBrush` | `#DCEBFA` / `#17202E` | `#264F78` / `#FFFFFF` | 自定义结果行的选中组合 |
| `NeteaseSuccessBrush` | `#067647` | `#75D69C` | 已连接、检测成功等状态 |
| `NeteaseWarningBrush` | `#8A5200` | `#FFB74D` | 试听、待重启等状态 |
| `NeteaseErrorBrush` | `#B42318` | `#FF8A80` | 错误及失败恢复提示 |

品牌红或微信绿只用于小面积品牌元素；有色按钮需要对应前景和交互状态，首轮优先使用当前主题的标准按钮外观。不得重新形成整块固定亮色账号卡片。

**二维码白底是明确例外。** 二维码图像与静区保留白底及黑色码点，外层提示、边框和操作仍随主题变化。头像、封面和二维码的图像像素不做主题反色；例外仅限内容区域，不能扩展到登录面板或整个 Document。

### 5.3 实机定位顺序

如果改完仍出现大面积浅色，按下面顺序记录证据，而不是继续叠加全局背景覆盖：

1. 核对 Host 实际加载的插件目录、程序集身份与当次构建产物，排除旧部署。
2. 核对应用、浮窗和根 View 的 `ActualThemeVariant`；确认 Host 的 Dark 已传播到该 View。
3. 从浅色区域的实际绘制控件向外查找 `Background`、局部属性值、样式与资源字典；区分根底色、音乐外层、列表模板和二维码白底。
4. 检查同名局部资源、一次性读取画刷的代码、菜单/Popup 和重挂后的资源上下文。
5. 只有证据指向 Host 时，单独记录跨仓缺陷；不将它自动扩成其他插件或主程序的改造任务。

## 6. 桌面密度与尺寸规则

单位均为 Avalonia DIP，以 **Document / Tool 获得的内容尺寸** 为准，不以整个显示器像素或 Host 总宽度判断。

| 项目 | 设计基线 |
| --- | --- |
| 正文字号 | 13；次要信息 12；局部分组 12–13 半粗；必要页内标题 16–18 |
| 内边距与间距 | Document 外侧 8–12，Tool 6–8；普通间距 4–8；去掉层层卡片内边距 |
| 控件高度 | 常用按钮/输入建议 28–32；结果单行建议 30–34；以 MinHeight 为主，避免放大字体后裁字 |
| 圆角 | 面板 0–4；头像与二维码等内容形状可保留专用处理 |
| Document 宽度 ≥ 900 | 歌曲、歌手、专辑、时长分列，播放条横向排列 |
| Document 宽度 640–899 | 收缩列间距，优先隐藏专辑列，播放条允许两行；主操作仍可见 |
| Document 宽度 480–639 | 歌曲与歌手合成两行结果；分页和播放控制分行；专辑进详情，登录内容按需局部滚动 |
| 更小 Document | 保留搜索、播放/停止与恢复入口，次要信息折叠或局部滚动；不强行把 Host 的最小窗口放大 |
| Tool | 验证宽度 280、320、420；另验底部停靠 640×240；单列表单不是手机化问题，重复大标题与过度留白才是 |

宽窄布局调整列、可见性和区域排列，保留同一个模型与输入状态。禁止用整体 `Viewbox` 缩小整个表单，或靠把文字降到 10–11 号来挤下所有操作。主题和尺寸变化不能丢失关键词、选择、设置草稿或键盘焦点。

### 6.1 现代样式的具体要求

- 默认即为紧凑密度，不新增“舒适 / 紧凑”等多套布局配置。顶栏、搜索区、列表和播放条对齐到同一边界，尽量用留白与底色差区分区域，边框只保留必要分隔。
- 主要操作有明确文字，辅助操作可用 14–16 DIP 矢量图标加提示；图标按钮点击区域保持 28–32 DIP。避免彩色 Emoji、渐变大按钮和不同风格图标混搭。
- 音乐品牌红只用于少量强调，普通内容保持中性色；选中、焦点、错误和试听各有独立语义。选中行使用背景与必要的细标记，不叠大阴影或发光效果。
- 搜索结果采用整齐的行和轻量悬停反馈；播放条使用小封面、清晰曲目信息与成组控制。空状态保留一句说明和一个有效操作，不使用占满工作区的插画或营销文案。
- 保持键盘焦点可见、按钮文字清楚和路径可复制。紧凑不降低可读性，也不靠极细低对比度文字制造“高级感”。

### 6.2 动效清单与时长预算

只对用户能感知的局部变化做有限过渡，统一使用简单缓出或线性曲线；交互命令立即执行，不等待动画结束。

| 触发 | 建议效果 | 时长 | 边界 |
| --- | --- | --- | --- |
| 按钮、图标按钮、结果行悬停 | 小面积背景/边框颜色过渡 | 80–120 ms | 只作用于当前交互项；键盘焦点即时可见 |
| 结果行选中变化 | 选中背景短过渡 | 100–140 ms | 不移动行、不缩放文字；列表刷新和滚动时不逐项入场 |
| 暂停/继续、检测结果等局部状态变化 | 图标或小状态区淡入 | 100–140 ms | 文字状态立即更新，快速连续变化覆盖旧动画，不排队回放 |
| 登录完成切换音乐主体 | 新内容一次轻淡入 | 120–160 ms | 只在真实阶段切换时触发；不创建第二份 ViewModel、不让整个窗口闪烁 |
| 展开详细信息 | 箭头旋转，内容可直接出现或短淡入 | 100–140 ms | 不逐帧插值容器高度，不让整个 Tool 连续重排 |
| 真实网络加载 | 现有小型不定进度条 | 仅请求进行且视图可见期间 | 请求结束、取消、隐藏时收口；不增加第二套忙碌动画 |
| 主题切换、窗口拖动、列表分页、播放进度更新 | 直接更新 | 无额外过渡 | 不全页渐变，不让每次播放进度或状态通知都触发动效 |

实现优先复用 Avalonia 原生 `Transitions` 和少量局部动画；不新增动画库、GIF、Lottie、WebView、着色器或自建逐帧定时器。需要变换时使用小范围 `RenderTransform`，颜色变化限制在小控件；大区域透明度动画也要实际测量，不能仅凭使用了 Opacity 就假设零开销。Avalonia 官方说明渲染变换不参与布局，而布局变换会触发布局计算，参见[变换与布局](https://docs.avaloniaui.net/docs/graphics-animation/render-vs-layout-transforms/)。

特别注意：Avalonia 的属性 `Transitions` **不会因为控件隐藏就自动暂停**，不能将 `IsVisible=false` 当作完成了动画清理。隐藏 Tool、切换到其他标签、脱离视觉树、窗口最小化或减少动态效果生效时，应取消自有动画、停止忙碌指示，并停止触发新的装饰过渡；重新可见时直接显示最新状态，不重播隐藏期间的变化。若 Dock 隐藏仍保持挂载，需结合控件有效可见性及顶层状态验证，不能只监听 Detach。参见[控件过渡](https://docs.avaloniaui.net/docs/graphics-animation/control-transitions)。

内容淡出不得留下透明但仍可点击、可聚焦的旧层；退出时及时撤销输入，动画结束或取消后完成可见性收口。优先只做新内容的短淡入，避免同时保留两份大内容树和位图。透明度为零仍可能接收输入，参见[Opacity 与 IsVisible](https://docs.avaloniaui.net/docs/graphics-animation/effects)。

### 6.3 资源与可关闭要求

1. **禁止常驻装饰动画。** 不做旋转唱片、跳动频谱、呼吸灯、背景流光、模糊玻璃、封面大阴影及歌词式自动滚动；音频进度继续按现有状态节奏更新，不追加渲染循环。
2. **动画期间不做业务和资源重建。** 不请求接口、不解码新封面、不新建 Bitmap、不重建结果集合或播放器；避免因动画使虚拟化列表全部实例化。
3. **提供一个“减少动态效果”选项。** 放在 Tool 底部“界面”分组，作用于本插件所有 Document 和 Tool；仅禁用本插件额外装饰过渡，标准控件行为由其主题负责。请求进度可退化为静态“加载中…”文字，焦点、错误和选中反馈保留。
4. 该选项用简单的插件 UI 偏好保存，独立于账号和 LibVLC 配置，不为此建立通用设置平台。默认允许上述轻量动效；若当前平台已有可靠的系统减少动画信号，则与用户选项共同取更保守的结果，不假设 SDK 已提供不存在的接口。
5. **以同机对照验证成本。** 用固定本地数据、无网络请求的同一页面，对比额外动效开/关的空闲状态、播放状态和快速操作；记录机器、缩放和采样条件。播放与请求自身开销单列，避免将 Host 整体 CPU 简单归因于动画。
6. 空闲且加载结束后不应存在本插件装饰性计时器或持续重绘；隐藏/最小化期间不持续产生装饰动画。反复交互、隐藏恢复和主题切换 20 轮后，不应有动画订阅、Bitmap 或 View 的持续保留增长。
7. 在实测机器上观察连续滚动和快速操作的帧时间与输入响应，60 Hz 显示以单帧约 16.7 ms 为观察预算；记录波动，不把该数值写成跨设备保证。若动效带来可重复的持续开销或卡顿，按“大区域淡入 → 变换 → 颜色过渡”的顺序简化，保留即时状态反馈。
