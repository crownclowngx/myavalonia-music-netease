> 更新：2026-09-23。状态：**V4.0 技术验证已完成，V4.1 起业务功能与完整 V4 门禁正在实施**。实际结果见[专用实施记录](../archive/records/netease-v4/m2-implementation-20260923.md)。
> 对应[能力路线图](netease-capability-roadmap.md)“M2：形成可日常使用的播放器”；V4 是实施文档编号，不是插件包版本。
> 源码核对基线：`afb3159`。承接 V2 单曲播放与 V3 桌面界面；M1 听感、真实 Host/Dock 及 V3 剩余实机验收继续保留，不因进入 M2 自动完成。
> 配套：[V4 / M2 专用开发验证矩阵](../maintenance/netease-v4-m2-daily-player-verification.md)。本文所有“新增”“调整”和目标行为均为待实施契约。

## 1. 目标与首要规定

用户能从自己的歌单持续听歌，管理共享队列，拖动进度并查看同步歌词；关闭音乐页面后继续播放，再打开仍控制同一播放器；重启后恢复上次队列，主动点击继续才出声。

1. **SOLID 是首要规定。** 按变化原因划分歌单读取、队列决策、单曲执行、歌词解析、状态存储和界面投影。每个阶段先检查依赖方向和资源所有权，再以功能与测试验收收口。
2. **设计模式朴素使用。** 沿用构造注入、端口适配、不可变快照与普通纯函数。四种模式用枚举和选择函数即可；不引入通用状态机、事件总线、CQRS、通用仓储、插件化播放策略工厂或大型继承体系。
3. **详细中文注释。** 解释设计原因、输入输出、线程、取消、重试、代次校验与资源释放顺序。公开契约及容易误改的竞态必须说明；不逐行翻译代码。
4. **单元测试与本地开发门禁齐全。** 正常、边界、失败、竞态、账号隔离、资源释放都纳入专用矩阵；测试结果映射到真实执行方法，自动结果、真实账号、实际出声与 Host 证据分开记录。
5. **代码与文档同步。** 每阶段更新当前契约、使用入口、专项验证及带日期的专用实施记录；没有实际运行的项目不能标为通过。
6. **不使用 AIFLOW，不新增或运行 Windows CI、发布门禁。** 本地 Debug 构建、测试、离线解码和真实 Host 开发联调属于本阶段。正式 ZIP、seal、发布 Smoke、发布覆盖率与重复性检查留到发布任务；本方案编写不触发部署。

## 2. 范围和完成边界

| 能力 | V4 必做内容 | 完成依据 |
| --- | --- | --- |
| 我的歌单 | 自建/收藏、分页、刷新、空态、失败重试、账号隔离 | 多页结果稳定；分类以当前账号 ID 与 creator 等真实字段判定 |
| 歌单曲目 | 有序 ID 快照、分批补详情、缺失占位、虚拟化列表 | 顺序和重复位置保留；播放全部包含已取得的完整 ID 快照，不只包含已渲染行 |
| 队列 | 播放全部、从选中曲目开始、下一首播放、追加、移除、清空、上一首/下一首 | 所有 Document 共用一份队列和当前项；操作结果确定 |
| 播放模式 | 顺序、列表循环、单曲循环、随机 | 手动与自然切换规则明确；所有不可播时有限停止 |
| 进度与缓冲 | 定位、拖动草稿、实际定位结果、缓冲反馈、有限恢复 | 完整本地缓冲可定位；失败不显示虚假新进度，不后台无限重试 |
| 歌词 | 逐行歌词、可用翻译、可用逐字歌词；跟随与恢复跟随 | V4.4a 先逐行，V4.4b 补翻译/逐字；缺轨道正常降级，不能默默删去逐字范围 |
| 最近播放与恢复 | 本地历史、按账号保存队列/模式/音量/位置、静默恢复 | 历史只记真实开始播放的歌曲；重新获取地址后才恢复播放 |
| 页面连续性 | 页面关闭继续播放、重新打开可控制、退出/关闭 Host 收口 | 无第二引擎、重复计时器或订阅；生命周期与持久化可等待 |

本轮不包含远端喜欢/收藏写入、编辑歌单、推荐/FM、下载/离线音乐库、桌面歌词、媒体键、Workflow、无缝衔接或跨淡化。队列调整只改变本地播放顺序，不修改网易歌单。保留 standard 资源策略及当前 Windows x64 实现边界。

## 4. SOLID 分工与对象寿命

以下是目标职责，不要求机械创建同名文件。优先修改现有代码，只在真实变化边界增设端口。

| 组件/区域 | 职责与寿命 | 依赖限制 |
| --- | --- | --- |
| `IPlaylistCatalogApi` / `NeteasePlaylistApi` | 我的歌单、详情、批量歌曲资料；无页面状态的 HTTP 适配 | 复用受控会话与传输；不下载媒体、不决定切歌 |
| `PlaylistBrowser` | 每个 Document 的分页、选择、刷新、请求代次、详情缓存 | 依赖歌单端口；向播放器提交有序条目快照 |
| `PlaybackQueueCoordinator` / `IPlayerSession` | 插件级唯一队列写入者，接受用户意图、选择条目、发布统一快照 | 组合现有单曲执行器、队列纯逻辑和存储协调；不解析 HTTP、LRC 或调用 LibVLC |
| `QueueNavigator` | 队列条目/模式/历史导航的纯计算；状态仅由队列协调者提交 | 不访问网络、磁盘、UI；随机源可注入确定性替身 |
| `PlaybackCoordinator` | 继续负责一首歌的详情、资源、缓冲、打开、暂停、定位及释放 | 所有终态携带 generation/原因；不能自行修改队列 |
| `ILyricsApi` / `NeteaseLyricsApi`、`LyricParser` | 前者读取歌词；后者把原始轨道转成有界时间轴 | 解析器是纯函数；损坏轨道不抛异常穿透到播放链 |
| `LyricsCoordinator` | 插件级当前歌曲歌词请求与同步索引，按播放代次拒绝旧结果 | 订阅播放器事实；不新建每页面播放时钟 |
| `IPlaybackStateStore` / 文件实现 | 按账号原子读写带版本的队列与最近播放 | 不保存会话、临时地址和音频；不修改共享 LibVLC 目录 |
| `PlaybackPersistence` | 插件级恢复、合并保存、最终 flush 与清理顺序 | 依赖存储端口、`TimeProvider`；不用 View 定时落盘 |
| `MusicWorkspace` 与歌单/队列/歌词子投影 | Document 级 UI 意图、显示与订阅 | 依赖窄业务端口；不读 Cookie、文件，不引用原生对象 |

调用路径为 `View → 页面投影 → 应用用例 → 端口的 Infrastructure 适配`；源码依赖方向始终是 Infrastructure 实现应用端口，应用层不引用 Infrastructure，由组合入口装配。`IPlayerSession` 只暴露队列/播放命令和脱敏快照，禁止暴露 `MusicSession`、路径和签名 URL。持久化协调接受值快照和返回恢复数据，不反向持有队列协调器，避免循环注入。Tool 继续只负责账号与设置；Standalone 复用同一对象图。

SOLID 审查逐项回答：S——类是否只有一种主要变化原因；O——新增模式能否只改导航规则及测试；L——替身与真实适配对取消、事件代次、停止后句柄释放是否遵守同一契约；I——歌词消费者是否被迫依赖歌单写入等无关能力；D——应用层是否只依赖业务端口和稳定数据，而非 Flurl/LibVLC/Avalonia 类型。简单纯函数不为满足字母数量额外建接口。

### 5.2 一致性与有界加载

- 歌单分页按 playlistId 去重，offset 按服务端本页原始条数推进，不能按去重后条数推进；重复页或无进展终止并提示刷新。服务端在分页期间修改列表时不承诺跨请求事务一致，刷新后建立新浏览代次。
- 歌单详情形成一次有序 ID 快照；每个位置有独立条目标识，重复歌曲仍保留不同位置。补详情可以乱序或部分缺失，按 ID 映射回槽位；缺失显示“资料暂不可用”，不删位置、不猜测 VIP 或下架原因。
- 默认每批 50 首详情、单页面同时最多 2 批；先填可见区域和当前播放所需项。请求合并仅针对同账号、同浏览代次和同一批 ID；不做通用全局缓存框架。
- 播放全部在快照完整、未超限时一次接纳全部 ID，再按需补资料。正在刷新或快照不完整时禁用“播放全部”，允许明确播放已知选中项，不能把截断列表称为全部。
- 初始本地预算：每账号最多展示 1,000 个歌单；单歌单/队列最多 10,000 个条目；页面完整歌曲资料缓存最多 500 条，已入队但未加载的条目只保留 ID/来源/必要展示。上限是产品保护值，V4.0 用大样本核验后可调整并同步测试与文档。
- 沿用 15 秒/1 MiB 业务响应预算。若完整 trackIds 超预算，先核对缩小 `n` 或端点专属有界预算；必须记录样本大小、解压上限和测试，不能全局去掉限额。无法确认完整性时显示限制并禁止“播放全部”。
- 手动刷新只替换浏览快照，已接纳队列保持独立；切账号立即取消旧请求并清空页面，账号 ID/epoch/浏览代次均相符才提交结果。

## 6. 队列、模式与并发契约

### 6.1 数据和用户操作

`QueueEntry` 至少包含独立 `EntryId`、`TrackId`、来源（搜索/歌单/历史及来源 ID）、可选展示资料；`CurrentEntryId` 表达实际当前项，列表选中项另存于页面。快照含 `AccountId`、`QueueRevision`、当前播放 generation、模式、状态、位置与操作能力，不含凭据。相同歌曲允许重复入队，删除一个 EntryId 不影响其他位置。

| 操作 | 明确语义 |
| --- | --- |
| 播放全部 / 从此处播放 | 原子替换队列；从第一项/指定位置开始，指定项之前的条目仍保留；清除旧随机轮次和优先序列 |
| 搜索或历史中直接播放一首 | 替换为单项队列并开始；需要保留原队列时使用“下一首播放/追加” |
| 下一首播放 | 创建独立条目，加入紧随当前项的 FIFO 优先段；多次操作保持操作先后；四种模式均优先消费 |
| 追加 | 加到队尾，不打断播放；空队列只入队并选中第一项，不自动出声 |
| 移除非当前项 / 调整顺序 | 不重启当前曲；按 EntryId 保持当前身份，修剪随机候选/优先段；UI 至少提供上移/下移，不要求拖拽 |
| 移除当前项 | 先取消旧曲并安全释放；按当前模式的“手动下一首”选剩余项，顺序模式删除末项则停留上一剩余项；有声时继续、暂停/停止/加载中时停在待播放状态，不突然出声 |
| 清空 | 先淘汰代次、取消加载并停止，清除当前项、优先段和导航历史；持久化空队列，迟到保存不得复活旧队列 |
| 停止 | 停止并将当前项位置归零，保留队列/模式；后续点击播放从当前项开头开始 |
| 手动上一首/下一首 | 先按模式选项；播放中或用户已发起的加载中继续新曲，暂停/停止/恢复待播时只换当前项并归零，点击播放才出声；上一首始终选前项，不隐含“超过几秒重播本曲” |
| 切换模式 | 当前曲和进度不变；进入随机时重建未访问候选，退出随机保留显示顺序；不触发地址请求 |

### 6.2 模式边界

正常曲间自动续播只由一次有效自然结束触发；不可播放候选的受控跳过单独遵循第 6.3 节预算。手动停止、取消、账号撤销、换曲产生的终态不得触发续播。

| 模式 | 自然结束（优先段为空时） | 手动下一首 / 上一首 |
| --- | --- | --- |
| 顺序 | 后一项；末曲保持 Ended，当前位置为结尾，停止续播 | 后一项/前一项；到首尾禁用对应操作，不回绕 |
| 列表循环 | 后一项，末尾回首项 | 后一项/前一项，首尾回绕 |
| 单曲循环 | 当前项重新开始 | 按列表移动并回绕；不能让用户按下一首仍回同曲 |
| 随机 | 以 EntryId 为单位无放回抽取，轮次结束重建；多于一项时不紧接重复当前项 | 下一首先走尚未回放的前进历史，否则抽取；上一首回到实际访问历史，无历史时禁用 |

优先段在自然结束或手动下一首时先于模式选择，上一首不消费优先段。随机模式消费优先项后从未访问候选移除对应 EntryId；删除条目同时修剪历史，重启不保存随机轨迹，重新建轮。单项队列在顺序模式自然结束停止，其他模式自然结束可重复；手动上/下一首禁用。空队列所有播放/定位/导航禁用。

### 6.3 失败和竞态

- 单曲无地址、详情缺失或明确内容不可用允许有限跳过；自动找歌的一轮中，每个 EntryId 至多尝试一次，最多 20 个候选，先达到者停止并给出汇总。单曲循环失败也按候选预算找其他项，不能原地死循环；全不可播时停下等待用户动作。
- 网络中断、限流、协议错误、磁盘问题、运行库/设备故障停止本轮自动推进，保留当前项供重试。不能把共享网络或设备问题当作每首歌不可播，轮询整张歌单。
- 可重试下载与地址过期共用“每次加载最多 3 次媒体请求尝试、地址重取最多 1 次”的预算。取消、越界来源、普通 403、解码错误和账号失效不自动重试；重定向仍独立受最多 3 跳约束。
- 同一当前代次的 Ended/Failed 只处理一次；记录终态原因并保证资源停止完成后才打开下一首。原生回调只入队通知，不能同步调用 Stop/seek。
- 用户快速 A→B→C、下一首与自然结束同时发生时，最后被接纳的有效意图决定当前项。队列意图在短临界区提交；网络与原生工作在锁外。先淘汰旧意图/播放代次再取消，不能让串行命令队列被慢下载占住而无法停止。
- `QueueRevision` 用于拒绝旧的批量入队/恢复结果，`EntryId + PlaybackGeneration + AccountEpoch` 用于控制与事件校验；追加非当前项不应使当前曲的自然结束失效。
- 播放命令接纳前可以被页面取消，接纳后只关联账号撤销和插件关闭；暂停、定位等命令携带目标 generation，等待原生门后再次核验，避免旧曲命令作用于新曲。

## 7. 定位、缓冲与恢复策略

V4 优先采用**完整临时缓冲 + 本地文件定位**。当前文件未完整下载时显示加载进度并禁用 seek；下载完成后 seek 无需请求 Range。网络断开不影响已完成缓冲的当前曲，只影响下一首加载。首播与曲间可能有下载等待，V4 不承诺无缝播放。

V4.0 必须验证锁定 LibVLCSharp/LibVLC 版本的可定位事实、MP3 与离线 WAV 的前后定位、暂停定位、近结尾与释放。如果完整文件定位无法通过，先记录原因、修复适配或更新本节方案及测试，再推进；不得直接把大规模流式缓冲改造混入实现。

- 新增 `CanSeek`、加载已读字节/已知总长及定位状态。未知长度用不定进度，不计算假百分比；加载进度只描述本次文件下载。
- 拖动期间 UI 保存独立目标位置，不被正常进度回推；松手一次提交，键盘操作合并提交。提交前重新核验 EntryId/generation，曲目变化即丢弃草稿。
- 目标限制在实际媒体与试听可播范围内；未知时长/不可定位时禁用。位置展示以原生确认事件为准，命令失败回到实际位置并提示；定位不改变暂停状态。
- 恢复续播需要“打开但不输出 → 定位 → 用户要求播放后输出”的适配语义，不能先 Play 再 Pause 导致开头短暂出声。若原生能力需通过启动参数完成，在 V4.0 离线 PCM 探针和实机验证后写入契约。
- 试听媒体时间与整曲歌词时间可能不同。资源模型保留经核对的试听起止字段；实测确定片段是否从零计时。没有可靠映射时显示试听及歌词同步受限，不自行猜 offset，更不能越过试听范围。
- 明确过期（当前是 HTTP 410）按需重取地址；可恢复网络错误最多一次延迟重试，延迟通过 `TimeProvider` 可取消。统一加载预算耗尽后由用户主动重试。不会因 UI 重挂重新计数或重取地址。

## 8. 歌词处理与同步

V4.4a 实现逐行闭环，V4.4b 在同一时间轴模型上补翻译与逐字。前者是中间交付，完整 V4 仍需验证后者；真实歌曲没有逐字数据时，缺失轨道属于正常状态。

- LRC 解析覆盖多时间标签、分钟/秒/不同小数精度、全局 offset、乱序、同时间多行、元信息和无效行；保留同时间原文顺序。时间统一为非负毫秒，不依赖当前系统小数文化。
- YRC 等逐字格式按 V4.0 确认的样本和独立期望时间轴测试；验证行/字时长、边界、重叠和异常数字。单一轨道损坏只降级该轨道，不阻塞播放。
- 翻译按时间关联，不能按数组下标硬配；无匹配翻译可以保留独立展示，不能错贴到另一句。先支持精确时间匹配，若上游存在系统偏差，记录样本后再增加有上限的匹配容差。
- 原始歌词先受 HTTP 大小限制；解析另限 10,000 行、100,000 个逐字片段。只缓存当前及最近 20 首解析结果，账号撤销清空，禁止无限缓存原始响应。
- 用实际 PositionMs 查询最后一个不晚于当前位置的行，seek 后重新二分定位，暂停保持高亮。逐字高亮使用同一媒体时间；仅当前可见行需要有限刷新，不能每字一个计时器或每个 Document 一套播放时钟。
- 无歌词、纯音乐、仅纯文本、缺翻译/逐字、请求失败分别可解释；失败提供手动重试，不触发换曲或退出账号。
- 用户手动滚动后停止自动跟随，显示“回到当前歌词”；换曲或点击该操作恢复跟随。隐藏/拆卸视图取消自有刷新，重新挂载从共享快照恢复。

## 9. 本地历史、存储和生命周期

### 9.1 数据与恢复

使用独立于会话与运行库设置的文件，例如数据根 `playback-state/<AccountId>.json`。路径仅由已验证的数字账号 ID 生成，文件内容有 schemaVersion、accountId、revision、队列 ID/来源、currentEntryId、mode、volume、positionMs 和最近播放。只保存必要展示文字，不保存 Cookie、临时 URL、媒体路径、音频或封面二进制。

- 最近播放：收到真实 Playing 且出现首个非 seek 的正常进度推进后才登记；加载失败、暂停恢复数据、单纯点选不计入。同一播放 generation 只登记一次，按 TrackId 去重并更新最近时间，最多 200 首；不调用远端听歌上报。
- 写入：队列/模式/音量等合并延迟 500 ms；正常播放位置每 5 秒保存一次，暂停和退出进程前 flush。使用快照、串行尾任务和原子替换，较旧 revision 不能覆盖较新状态。
- 读取：单文件最多 4 MiB，验证账号、schema、条目数量、正数 ID、当前项引用、音量和位置；损坏或未知新版本显示恢复失败并保留原文件供排查，不自动把空状态覆盖过去。旧的 `playback-settings.json` 和 `ui-preferences.json` 无需迁移。
- 写入同样检查 4 MiB 上限；限制可选展示文字长度，必要时省略可重取的文字，不截掉队列条目冒充保存成功。损坏/未知版本文件只在用户明确新建或替换本地状态后覆盖，不能由初始化或定时保存擅自覆盖。
- 恢复：账号核验成功后才读该账号文件；只恢复队列、显示及待续播位置，呈现“已暂停，点击继续”。不解析地址、不建音频媒体、不发声；期间新的用户操作优先，迟到读取不得覆盖新队列。
- 点击继续：重新解析当前权限与地址，重新完整缓冲，校正实际时长/试听范围后定位并播放。若续播位置超过新媒体结尾，重置为 0 并提示；定位失败则保持可重试状态，不假称已续播。
- 保存失败不影响当下播放，显示“本地恢复未保存”并提供重试/下次变更再保存；磁盘失败不会自动退出账号。

### 9.2 关闭和账号变化

| 事件 | 必须行为 |
| --- | --- |
| 页面切换、View 脱离、Dock 浮动/隐藏、关闭任意或最后一个 Document | 只释放该页面工作和订阅；已接纳播放与队列继续；再开页面直接显示共享状态 |
| 用户停止/清空 | 按第 6 节控制音频并保存结果；不能让挂载、动画或歌词触发自动重启 |
| 显式退出账号 | 立即撤销代次、取消所有个人请求、停止音频、清空内存队列/历史/歌词/页面；删除该账号的队列与续播状态，保留按账号隔离的本地最近播放；保留运行库和界面偏好 |
| 会话失效 | 立即停止并清空可见个人数据，保留该账号最后有效的磁盘恢复记录；重新核验同账号后仍须主动继续 |
| 账号 A 切到 B | A 的迟到 HTTP、歌词、存储回调不能污染 B；不同账号文件与内存分区一致；经显式退出进入 B 时遵守上述清除规则 |
| Host Shutdown / Standalone 主窗关闭 | 拒绝新意图，捕获停止前位置、取消网络/歌词、停止输出、等待最后保存和清理，再释放单曲/登录/容器；重复关闭等待同一任务 |

显式退出的“删除续播状态”要与已排队保存串行，先使旧写入资格失效，再执行最终清理；清理失败必须可见且可重试，不能报告已清理成功。新账号不等待旧页面重建才隔离。Standalone 主窗关闭是进程级终止，与 Host 里关闭一个 Document 不同，禁止仅移除页面 Stop 后遗漏容器收口。

## 10. 界面落点与中文注释

保留 V3 紧凑布局、Light/Dark 资源、减少动态效果与固定底部播放条。主内容增加“搜索 / 我的歌单 / 最近播放”入口，歌单详情使用虚拟化行；队列和歌词用可切换面板，窄宽度下切换主内容，不横向堆满三栏。底部提供上一首、播放/暂停、下一首、模式、seek、音量和加载/试听状态。

Document 验收沿用 1200×720、800×600、520×420；Tool 沿用 280/320/420 宽及 640×240 底部形态。按钮提供中文名称、提示和键盘焦点；搜索分页命令改用清楚的 `NextSearchPageCommand` 等命名，避免与播放下一首混淆。两个 Document 可以浏览不同列表，但播放条/队列一致；当前播放与页面选择有独立标识。

新增契约的中文注释至少回答：为什么独立 EntryId；为什么先淘汰代次再取消；哪些终态允许续播；为何退出清理排在旧保存之后；为什么不在原生回调 seek；为什么恢复不打开音频；每个上限与降级的设计原因。示例：

```csharp
/// <summary>
/// 接纳一次队列播放意图。页面令牌只控制接纳前的取消；接纳后由账号与插件寿命拥有，
```
