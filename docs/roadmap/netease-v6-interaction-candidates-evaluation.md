## 1. 这份文档如何评估

核心方向是：**浏览内容、控制播放、查看歌词互不打断；辅助信息按需展开，操作后有准确反馈。**

本轮列出 18 个候选项，包括用户明确提出的歌词抽屉、与抽屉配套的改造，以及播放、搜索、队列和阅读方面的增强。它们不是一份默认全部实施的清单。

第 4 节可直接填写“采纳 / 调整后采纳 / 暂缓 / 不做”。也可仅回复编号，例如“01、02、06、07、08、10、15 先做，03 暂缓”。编号固定，后续修改文档、测试与实施记录继续引用，不因排序而重编号。

用户已明确歌词抽屉方向；抽屉的具体交互参数和其他候选仍待评估。未选择的可选功能不进入本轮验收分母；选中功能的正确性、SOLID、必要测试和文档同步则是必须满足的条件。

## 3. 当前基线：已有能力与实际差项

### 3.1 直接复用，不重复建设

- [MusicView](../../src/MusicNetEasePlugin.Plugin/Features/Music/MusicView.axaml) 已有固定底部播放条和右侧队列容器。当前歌词占主内容区，队列在宽屏并排、窄屏切为主内容页。
- [MusicNavigation](../../src/MusicNetEasePlugin.Plugin/Features/Music/MusicNavigation.cs) 保存浏览页，但显示歌词会隐藏搜索、歌单或历史；这是抽屉改造的关键状态差异。
- [LyricsView](../../src/MusicNetEasePlugin.Plugin/Features/Music/LyricsView.axaml.cs) 和 [LyricsWorkspace](../../src/MusicNetEasePlugin.Plugin/Features/Music/LyricsWorkspace.cs) 已有同步高亮、翻译、手动浏览暂停跟随、回到当前歌词、失败重试与可见性控制。现有滚动是 `ScrollIntoView`，不能描述为已实现平滑居中。
- [播放条](../../src/MusicNetEasePlugin.Plugin/Features/Music/PlaybackBarView.axaml) 已有音量弹层、静音恢复、四模式、失败提示和重试；[定位模型](../../src/MusicNetEasePlugin.Plugin/Features/Music/TimelineWorkspace.cs) 已有拖动草稿和单次提交，不需要重写音量或定位基础能力。
- [队列界面](../../src/MusicNetEasePlugin.Plugin/Features/Music/QueueView.axaml) 和 [队列模型](../../src/MusicNetEasePlugin.Plugin/Features/Music/QueueWorkspace.cs) 已有定位当前项、上移/下移、移除及带版本校验的清空确认。拖拽、撤销应作为增量，不能把这些已有功能重新记作新增。
- 当前多个 Document 共享账号、队列和播放器，各自保留浏览状态。关页、重挂和隐藏界面不应停止音乐。

## 5. 歌词与抽屉：具体体验建议

### V6-01 · 右侧歌词抽屉

- **操作效果：** 点击底部“歌词”或现有封面入口，右侧展开；再次点击或使用“收起”关闭。按钮准确表达开关状态。浏览页、关键词、页码、选中项和滚动位置保留。
- **空间建议：** 抽屉从搜索和导航下方开始，到播放条上沿结束。默认宽 360 DIP；宽屏并排，空间不足时覆盖内容区。初始判断可采用“剩余浏览宽度至少约 620 DIP”，数值待布局验证，不按显示器物理分辨率判断。
- **内容：** 歌名、歌手、小型操作区、歌词和可选翻译；默认不展示占空间的大封面。建议 180–220 ms 一次性过渡，减少动态效果开启时直接切换。
- **边界：** 窄屏覆盖态无全窗遮罩，不锁住播放条；建议只通过明确关闭动作收起，浏览操作不自动关掉歌词。每个 Document 独立开关，关闭后明确停用歌词 UI 刷新，不能仅移出屏幕。新建 Document 默认关闭；示意图默认展开仅用于评估效果。
- **验收重点：** 开关不请求重播、不新增播放器、不重建浏览模型；快速反复开关最终状态正确；关闭过程后没有不可见面板截获输入。

### V6-02 · 歌词与队列共用抽屉

- **操作效果：** 点击“队列”把同一个抽屉切换到队列，再点“歌词”切回；一次只显示一种内容。重复点当前按钮关闭。
- **保留内容：** 两个面板分别记住本次 Document 的浏览位置；共享外壳不等于共享滚动位置。切歌继续使用现有同步逻辑。
- **设计边界：** 浏览页与侧栏状态正交。拟采用 `BrowsePage = Search / Library / History` 和 `SidePanel = None / Lyrics / Queue`，避免多个开关组合出“歌词和队列同时抢主区域”的状态。
- **验收重点：** 任意顺序切换、跨布局断点、开关设置后返回，浏览页及侧栏状态一致；只有当前面板参与输入和必要视觉刷新。

### V6-03 · 抽屉宽度调整与记忆

- **操作效果：** 拖动左侧分隔线调整宽度，建议范围 320–480 DIP；提供键盘调节和“恢复默认宽度”。此项不选时固定 360 DIP 即可。
- **记忆建议：** 用户偏好保存“希望使用的宽度”，实际宽度受当前可用空间约束。缩窗造成的临时收窄不覆盖偏好；拖动结束再保存，避免每个像素写文件。
- **状态归属：** 宽度可作为同一插件容器共享的布局偏好，抽屉是否打开仍属于各 Document。退出登录不保存歌词、歌曲或浏览内容到布局偏好中。
- **验收重点：** 拖动途中失去捕获、切换 DPI、拖出 Dock、保存失败与旧配置迁移；最窄布局保留关闭入口和底部播放控制。

### V6-04 · 当前歌词舒适定位与轻量滚动

- **操作效果：** 跟随模式下，让当前句靠近歌词视口中部，保留前后文；切句做短距离平滑过渡。逐字高亮仍复用现有真实播放位置。
- **尊重阅读：** 滚轮、拖动和键盘浏览后停止自动跟随，“回到当前歌词”明确恢复。建议同一首歌收起再展开保留手动浏览状态；处于跟随模式时则立即定位最新一句，换歌恢复跟随。
- **性能边界：** 只在换句、恢复跟随或必要布局变化时滚动，不按每个进度 tick 发起滚动；隐藏、减少动态效果和旧滚动取消都要处理。
- **验收重点：** 长句换行、翻译增加高度、虚拟化未实现目标行、快速 seek、连续换歌时不争抢滚动；不能把取消后的滚动套用到新歌。

### V6-05 · 歌词“跳到此句”

- **操作效果：** 在歌词行菜单提供“跳到此句”，键盘也能触发。默认单击继续用于选择或阅读，不单击即跳转；双击播放是否启用留给用户另行选择。
- **播放语义：** 跳到该句时间并保留原播放/暂停状态。如果另设“从此句播放”，必须明确它会恢复播放，两个含义不混用。
- **资格边界：** 仅有可信同步时间、有效曲目身份且播放器可以定位时可用。纯文本、未知时间映射的试听片段、时长未知和切歌途中给出具体不可用原因，不猜测时间偏移。
- **验收重点：** 提交绑定队列项和播放代次；选择旧歌词后切歌，不得定位新歌；同一操作只提交一次，失败不伪造播放进度。

## 6. 播放与反馈：具体体验建议

### V6-06 · 播放忙碌态与不可用原因

- **操作效果：** 主播放键保持位置，加载时显示明确忙碌态；等待音频、正在定位、播放失败有各自文案。不能定位时在相邻位置提供可读原因，而非仅把进度条变灰。
- **复用基础：** 失败持续提示和重试已存在，此项补齐状态表达。主按钮的动作、图标、可用性和可访问名称必须一致。
- **边界：** 减少动态效果时使用静态加载标识；隐藏页面不维持装饰时钟。原因只能来自当前真实状态，不把所有失败都归因于网络。
- **验收重点：** 加载→成功、加载→失败、失败→重试、加载中换歌、暂停定位等组合；不留错误图标或可触发的旧命令。

### V6-07 · 准确的队列操作反馈

- **操作效果：** “已加入队列 · 本次 3 首”和“将在当前歌曲后播放”分别反馈；重复曲目未新增、达到上限或部分失败也有准确结果。
- **设计思路：** 从实际操作结果生成提示，不通过“队列数量增长”推断用户意图。正常反馈就近短暂显示，错误保留可查看入口。
- **边界：** 快速操作合并或替换为有界的一条反馈，不堆叠遮挡控制；不会把另一个 Document 的动作错误地报告为本页本次操作。
- **验收重点：** 追加、下一首、无新增、批量与并发结果均匹配；提示寿命结束或页面关闭后，不留计时器和旧反馈回写。

### V6-08 · 可收起的继续播放提示

- **操作效果：** 静默恢复后显示“已恢复 12 首 · 上次停在 01:23”，提供“继续播放”和“收起”。继续入口无需先打开详情弹层。
- **状态建议：** 提示位于内容区的紧凑状态行，最多占一行常规高度；低矮布局折叠为可访问入口，不无限拉高播放条。
- **边界：** 恢复仍保持暂停；用户主动继续才获取音频和出声。主动点播新歌后旧恢复提示失效，收起不删除恢复队列；当前会话不反复打扰。
- **验收重点：** 空队列、缺失旧曲目、恢复迟到、两个 Document 同时继续、恢复后退出账号；显示数量与位置必须来自有效恢复结果。

### V6-09 · 进度条悬停与拖动预览

- **操作效果：** 鼠标悬停显示对应时间，拖动时目标时间跟随滑块；可选增加已加载同步歌词的短文本预览。键盘调节同样能看到目标时间。
- **复用基础：** 现有拖动草稿、松开单次提交和真实播放事实继续使用；预览本身不 seek、不新取歌词、不输出音频。
- **边界：** 歌词预览依赖有效同步时间，缺歌词时退回时间；离开、失去捕获、关闭页面或切歌立即取消预览，不显示上首歌词。
- **验收重点：** 首尾限位、RTL/布局坐标如涉及、未知时长、试听、拖动时切歌、连续键盘调节；触屏不依赖 hover 才可操作。

### V6-10 · 低矮窗口的紧凑播放条

- **操作效果：** 小窗口优先保留播放/暂停、上下首、进度和歌词入口；音量仍用已有弹层，其他辅助动作按剩余空间收纳到“更多”。
- **设计思路：** 按控件实际空间与文字量收纳，不无限缩小字号，也不因出现提示再追加若干行。沿用现有布局目标，并在修改文档中确定具体高度预算。
- **边界：** 不做第二套播放器或独立迷你窗口；状态、快捷键与命令继续共用。高 DPI 与长中文必须参与断点验证。
- **验收重点：** 至少覆盖 1200×720、800×600、520×420 DIP 的 Document，分别开关抽屉、出现错误和加载状态；核心命中区域不得被覆盖。

## 7. 浏览、信息与辅助操作：具体体验建议

### V6-11 · 页面内快速搜索与清空

- **操作效果：** 音乐 Document 获得焦点时，`Ctrl+F` 定位现有搜索框；有文字时出现清空按钮。继续使用 Enter 提交，不默认改为逐字网络搜索。
- **输入边界：** 中文候选确认不能提交搜索；菜单、弹层先处理自己的按键。搜索框 Esc 清空是否需要可独立选择，不覆盖已有抽屉关闭和输入法语义。
- **状态边界：** 清空文字不擅自开始播放或刷新全部数据，提交新搜索才改变搜索结果；请求乱序仍只接受最新有效结果。
- **验收重点：** IME、焦点不在音乐页、多个 Document、Shift+Tab 和连续提交；不注册全局系统快捷键。

### V6-12 · 清楚的空态、加载和重试

- **操作效果：** 初次搜索显示引导，无结果提示换关键词，空队列提供浏览入口，网络失败就地重试，部分加载保留可用数据并说明范围。
- **减少闪烁：** 辅助加载提示可延迟约 150 ms 再显示，但请求状态与防重复提交立即生效；快速完成则不闪过一条加载动画。
- **边界：** 复用已存在的歌词/播放错误入口，避免双重报错。旧请求迟到不能把新结果改为加载或错误，取消操作不显示为失败。
- **验收重点：** 初始、忙碌、空、失败、部分成功各态都有准确且可执行的下一步；使用可控时钟验证延迟，不靠长时间 sleep。

### V6-13 · 完整曲目信息按需查看

- **操作效果：** 播放条空间允许时显示歌手；长歌名、歌手、专辑可通过提示或简短详情弹层完整查看，键盘焦点与触屏均有入口。
- **复用基础：** 歌曲标题提示已经存在，重点补歌手、专辑和窄行入口；优先使用当前已加载资料。
- **边界：** 本项只查看信息，不自动增加歌手页、专辑页、下载或收藏操作，也不因 hover 发起额外网络请求。
- **验收重点：** 超长中文、多歌手、字段缺失、换歌时弹层打开、窄屏与读屏；内容完整但不能溢出可用窗口。

### V6-14 · 歌单详情的简洁头部

- **操作效果：** 宽屏增加小封面、标题、数量与主要播放动作，描述按需展开；窄屏和低矮窗口自动压缩，歌曲列表优先获得空间。
- **信息边界：** “已加载 N 首”和“完整歌单 M 首”区分，资料不完整时不暗示已加载全部；返回继续保留原筛选和滚动位置。
- **资源边界：** 复用现有缩略图与图片租约，不增加大背景、模糊或单独下载；没有描述字段则不造占位描述。
- **验收重点：** 长描述、无封面、部分加载、取消加载和返回；展开描述不把播放控制推离视口。

### V6-15 · 键盘、焦点与可访问性补齐

- **操作效果：** 导航有正确选中语义，歌词/队列按钮有展开状态；键盘打开抽屉后进入首个可操作项，关闭回到有效触发入口。
- **焦点规则：** 非模态抽屉不设置焦点陷阱，Tab 可到浏览区和播放条。关闭入口已销毁时回退到播放条相应按钮；Dock 重挂后不把焦点还给旧控件。
- **按键规则：** Esc 先由当前弹层处理，再关闭抽屉；输入法组合及已处理事件优先。Space 不抢文本、滑块、按钮和列表自身语义。
- **验收重点：** 真实控件事件、键盘完整路径、屏幕阅读器名称和状态播报；不逐句逐字播报歌词，不把纯模型调用当作焦点验收。

### V6-16 · 队列拖拽排序

- **操作效果：** 通过明确拖动手柄移动队列项，显示插入位置；保留现有上移/下移作为键盘和精确操作入口。
- **设计边界：** 所有改动仍交给唯一队列写入者，以 EntryId 区分重复曲目。拖动预览不在每次鼠标移动时提交排序。
- **一致性：** 拖动期间切歌或另一个 Document 改队列，释放时校验有效版本；不适用时取消并说明，不能按旧索引移动另一首歌。随机模式仍明确“列表顺序不等于实际下一首”。
- **验收重点：** 重复 TrackId、虚拟化、列表边缘滚动、移出窗口、Esc 取消、当前项移动和并发改队列；新增交互不能误触播放。

### V6-17 · 移除 / 移动的单步撤销

- **操作效果：** 完成一次移除或移动后提供“撤销”。第一版建议只保留最近一次、仍可安全撤销的操作，不增加多级历史栈。
- **正确性边界：** 记录账号、目标队列项、必要顺序信息及操作后版本。只有同账号且队列版本仍适用时恢复；发生后续队列变更则取消撤销资格，并可解释原因。
- **播放边界：** 撤销只恢复适用的队列结构，不重启已停止媒体，不回退真实播放进度，也不自动把已切换歌曲切回。清空队列仍沿用现有确认，不并入首版撤销。
- **验收重点：** 删当前项、重复曲目、多个 Document、退出重登、容量已满、连续两次操作、迟到撤销；恢复必须由唯一写入者原子校验，不能 UI 先校验再分步改队列。

### V6-18 · 紧凑 / 舒适阅读密度

- **操作效果：** 设置提供两个明确档位，调整行高、间距和必要字号；信息量与点击空间可以按个人习惯选择。
- **默认建议：** 延续现有密度作为默认，不同时增加多组字体、颜色和动画开关。歌词字号是否单独调节留到评估后确定。
- **设计边界：** 统一通过插件样式和少量偏好实现，不在每个 View 散落条件；更改密度不重建播放或浏览模型。
- **验收重点：** 老配置迁移、保存失败、深浅主题、长中文、虚拟化行高度变化、切档后选中与滚动保留；两档均满足命中区域与可读性。

## 8. 建议的选择顺序与暂不合并范围

建议先评估以下组合，最终以用户选择为准：

1. **抽屉基础：** V6-01、02，加上 V6-15 中必须配套的焦点、按键与名称部分。解决当前最明确的空间和切页问题。
2. **高频体验补齐：** V6-06、07、08、10、12、13，并完成 V6-15 的整页补齐。让播放状态、操作结果和小窗口体验更清楚。
3. **按使用频率增强：** V6-03、04、05、09、11、14、18。喜欢看歌词可优先 04/05，常用键盘可优先 11。
4. **队列复杂操作：** 经常整理长队列时再选择 V6-16、17；两项可分开，不为拖拽预先构造通用撤销框架。

喜欢/收藏、歌单写入、推荐、下载、桌面歌词、系统媒体键、独立迷你窗口、睡眠定时与封面取色等可继续评估，但不自动合并到本次改造。它们已有或适合独立的能力/系统集成范围，见 [能力路线图](netease-capability-roadmap.md)。

## 9. 实施时的设计原则草案

本节约束选中项的实现方式，不预先冻结类名、控件模板或代码改动清单。

### 9.1 SOLID 检查点

| 原则 | 本项目中的要求 |
| --- | --- |
| 单一职责 S | 导航模型只负责浏览与面板状态；View 负责输入、焦点和布局；歌词模型负责展示投影；播放和队列规则继续由既有应用服务负责 |
| 开闭原则 O | 用现有歌词/队列视图组合出抽屉，通过明确状态增加入口；避免复制第二套播放条、网络请求或歌词协调器；不为假想的十种侧栏建立框架 |
| 里氏替换 L | 假播放器、存储和调度器遵守真实的异步、取消、失败及时间语义；不靠“测试替身永远成功”掩盖生产约束 |
| 接口隔离 I | 继续使用最小必需端口；若新增操作结果或偏好契约，只暴露使用方需要的数据；不增加集 UI、HTTP、音频、存储于一体的大接口 |
| 依赖倒置 D | 展示模型通过现有抽象使用播放、调度和存储；XAML 后台不直连 Flurl、LibVLC 或 Host 内部类型；组合仍在插件注册根完成 |

状态归属建议：

| 状态 | 所有者 / 生命周期 |
| --- | --- |
| 当前浏览页、侧栏内容、列表位置、焦点回退 | 每个 Document 的导航/视图状态 |
| 播放事实、队列版本、歌词时间轴 | 现有插件容器级播放与歌词服务 |
| 拖动草稿、滚动动画、临时提示 | 对应页面或操作范围，可取消，关闭后释放 |
| 用户宽度/密度/减少动效偏好 | 现有偏好服务；仅选中相应候选时扩展和迁移 |
| 队列撤销资格 | 唯一队列写入者核验的当前操作数据，不由视图自行还原快照 |

宽窄布局只改变呈现，不改播放、账号或队列语义。选择 `SplitView` 或现有 Grid 组合前，先验证非模态输入、关闭后的可见性和已有主题适配；不为了某个控件牺牲这些交互要求。

### 9.2 朴素使用设计模式

优先采用现有 MVVM、构造注入、枚举状态、少量纯计算函数与明确的取消/释放。仅在选中候选存在真实变化点时引入小型策略或结果类型，不建设通用面板引擎、事件总线、服务定位器、工作流引擎或多级命令框架。

特别注意：抽屉是音乐 Document 内部布局，不增加 Host Dock Tool，也不重新登记 Host 拥有的贡献根。依赖注册继续回归 V5 已修复的所有权约束。

### 9.3 中文注释与设计思路

注释至少覆盖：状态为何分离、参数单位和限位原因、请求/播放身份为何校验、隐藏为何停止刷新、取消后为何忽略迟到回调、所有权和释放顺序。

示例仅表达注释质量，不是待直接粘贴的实现：

```csharp
// 浏览页和侧栏分别保存，打开歌词只改变侧栏状态。
// 这样切换歌单、收起歌词或 Dock 重挂时，原搜索结果与列表位置仍由原页面持有，
// 不需要重新创建浏览模型，也不会触发无关的网络请求。

// 抽屉移出屏幕并不一定意味着控件已不可见。
// 关闭完成后要明确暂停歌词视图的进度投递；再次打开时读取最新快照。
// 播放器和共享歌词时间轴继续运行，不能随抽屉关闭而被释放。
```

公共契约写明输入、输出、取消、失败及线程假设；XAML 后台只注释必要的输入路由和视觉寿命，不放业务规则。复杂取舍在专用修改文档记录，代码注释标明维护时不能破坏的原因。

### 10.3 本地开发门禁

当前可执行入口仍为：

```powershell
pwsh -NoProfile -File tools/verify-development.ps1 -Milestone V5
```

当前脚本尚不接受 `V6` 参数。本轮不加空壳参数、不伪造 V6 映射。实施阶段复用此脚本体系，在真实测试和证据校验落地后增量支持 V6，并保留适用的 V1–V5 回归。

门禁顺序沿用既有惯例：自身失败注入 → 锁定依赖恢复 → Debug 构建且警告视为错误 → 全部适用测试 → TRX 与必需场景映射 → 必需资源/布局证据 → Markdown 链接与补丁格式 → 验证期间源码一致性。

新增或修改门禁时，至少自测以下失败：

| 失败类型 | 必须表现 |
| --- | --- |
| 测试失败、必需测试跳过、零执行或统计不一致 | 非零退出，不能报告通过 |
| 选中必需场景缺映射、映射到不存在的方法 | 报告具体缺项，不能靠展示名称或测试总数充数 |
