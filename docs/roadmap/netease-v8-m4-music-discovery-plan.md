# V8 · M4 从“找歌听”扩展到“发现音乐”实施计划

> 编写日期：2026-09-25。状态：**计划已编写，V8 业务代码、专用门禁和真实环境验收尚未实施**。
> 承接[能力路线图](netease-capability-roadmap.md)的 M4；V8 是计划 / 实施序号，不是插件包版本。测试与证据要求见[V8 专用验证矩阵](../maintenance/netease-v8-m4-music-discovery-verification-plan.md)。
> 首要规定：**满足 SOLID**；设计模式朴素使用；新增与修改的关键代码使用详细中文注释并说明设计思路。全过程不使用 AIFLOW、Windows CI 或发布门禁；正式发布时另行开展发布验证。

## 1. 目标与执行边界

让用户能够“打开推荐或榜单 → 选择歌曲播放 → 进入歌手 / 专辑继续发现 → 用私人 FM 连续听歌 → 按来源查看远端听歌记录”。新入口使用现有账号、共享队列、播放资源解析、歌词、喜欢 / 收藏和图片服务。

开发优先级依次为 SOLID 与状态正确性、可测试性、功能闭环、交互完整性。不得为赶进度将端点解析、FM 调度、页面导航和远端写入堆入 `MusicWorkspace` 或 `PlaybackQueueCoordinator`。

本计划覆盖路线图 M4 的五组能力，顺序固定为**推荐 / 榜单 → 歌手 / 专辑 → 私人 FM → 远端历史**。可以按阶段交付，但仅实现推荐页不等于 M4 完成。自动播放事件上报独立保留为后续小项；V8 不调用 `scrobble`、`scrobble_v1` 或其他打卡 / 播放上报接口。

本次文档工作只新增计划、验证矩阵和导航入口，不改业务、包版本或门禁默认值，不预填测试通过数。后续实施只执行本地开发门禁；允许在 Windows x64 本机进行 Debug 构建和测试，不新增 / 触发 Windows CI，不运行发布构建、发布 ZIP、签名、上传或发布 / 部署门禁。

完成标准分三层记录：

1. **阶段实现完成**：对应功能、错误 / 取消分支、中文注释及场景测试落地，相关文档同步。
2. **V8 开发完成**：V8-01～10 全部实现，完整 V8 本地门禁及适用旧版回归通过，证据有实际来源。
3. **M4 验收完成**：真实账号、真实 Host、声音 / 物理输入等专项验收完成，用户确认后再勾选路线图 M4。自动测试不能替代这一层。

M3 已通过本地验证但真实验收尚未完成；V5 / V6 的[待验事项](../maintenance/netease-v5-v6-acceptance.md)继续单列。V8 可以复用其实现，不能因此将旧验收状态改为完成。

## 4. SOLID 与朴素设计

### 4.1 约束落实到职责

| 原则 | 本阶段必须满足的要求 | 评审时的检查方法 |
| --- | --- | --- |
| S · 单一职责 | HTTP 适配器只解释端点；浏览模型只管理页面投影；FM 服务只负责会话、内容预算和反馈意图；队列仍负责原子接纳与播放导航 | 页面无 JSON / 协议码处理，FM 不持有音频句柄，队列不解析推荐响应 |
| O · 开闭原则 | 推荐 / 榜单通过新增内容适配和页面接入；为 FM 提供一个受约束的供应边界，保留现有四模式路径 | 不在搜索、歌词、播放资源解析中散布来源字符串判断；不为未来所有内容搭框架 |
| L · 里氏替换 | Fake 和真实端口对取消、分页终止、缺身份、空结果和写入未知遵守同一契约 | 对两种实现运行相同边界断言；Fake 不把所有错误变为空成功 |
| I · 接口隔离 | 只读推荐、作品目录、FM 内容、FM 反馈和远端记录分开；浏览调用方不获得写入口 | 按消费者需要拆小端口，不能建立含全部网易接口的大接口 |
| D · 依赖倒置 | 应用依赖端口、会话访问器和 `TimeProvider`，Infrastructure 提供 Flurl 实现，组合根注入 | 业务单测不启动 UI / WebView / LibVLC；应用层不读取全局服务定位器 |

继续使用普通 MVVM、构造注入、类型化结果、不可变快照、现有事件和简单条件分支。有限 FM 状态用枚举与显式转移表达即可，不建设状态机框架、通用仓储、消息总线、CQRS、工作流引擎或插件式推荐策略系统。接口仅用于确有替换 / 测试需求的边界，不给每个纯函数类套接口。

### 4.2 建议代码位置与寿命

以下均为**拟新增或扩展**，类型名称可随评审调整，职责与所有权不能混淆。

| 位置 / 建议对象 | 职责与寿命 |
| --- | --- |
| `Application/Discovery/DiscoveryContracts.cs` | 推荐 / 榜单查询端口及来源、完整性、抓取时间等类型；无控件、HTTP DTO 和凭据 |
| `Application/Discovery/ArtistAlbumContracts.cs` | 歌手 / 专辑最小身份及分页作品端口；保留歌手次序、专辑 ID 和未知资料 |
| `Application/Discovery/PrivateFmCoordinator.cs`、FM 小端口 | 容器共享的 FM 会话、内容获取、去重窗口、有限补取及反馈结果；网络期间不占队列锁 |
| `Application/Discovery/RemoteHistoryContracts.cs` | 远端最近及排行的查询边界；记录来源 / 范围，不写本地播放历史 |
| `Infrastructure/Http/Netease*DiscoveryApi.cs` 等薄适配 | 按上述消费者分组，复用传输、编码和会话保护；响应解析不泄漏到应用层 |
| `Features/Discovery/` 中浏览模型及 View | 每 Document 独立导航、分页、选中、取消和图片租约；通过端口提交播放及 FM 意图 |
| `Features/Music/HistoryWorkspace.cs` 和历史 View | 承接三种历史来源切换；本地历史原算法和存储不改写 |
| 既有队列、注册及寿命入口 | 增加最小 FM 原子接纳 / 终态供应协作，维持唯一写入者；Stop / Clear / Logout / 最后页关闭撤销 FM 资格 |

避免双向构造依赖。可由组合根将小型 FM 内容供应端口注入队列，并将同一 FM 服务提供给页面；FM 服务返回带身份的供应结果，不能反向调用队列进行第二次推进。若需要通知，仅发布有限的失效事件，消费方负责解订阅，不捕获 View / Document。

### 5.2 身份、来源与兼容性

- 扩展歌曲模型时保留既有名称展示，增加可选 `ArtistRef` 列表与 `AlbumRef`（名称可缺省，ID 必须可信）；多个歌手不得合并为一个可点击字符串身份。搜索、单曲详情、歌单批量资料和新增端点统一解析这些字段。
- 无有效歌手 / 专辑 ID 时显示普通文本。用户主动打开作品入口时可以使用既有歌曲详情补全一次，不在每行渲染时发请求；补全仍缺身份则说明不可用，不按名称猜测。
- 旧持久化歌曲资料没有新字段时仍可恢复，保持静默；若调整存储 schema 必须有迁移 / 未来版本保护测试。不得为了作品跳转在恢复阶段自动联网。
- 发现快照至少区分来源、账号 Epoch、抓取时间、请求代次、已加载数量、服务端总量（可未知）、分页游标 / offset、是否完整 / 截断。页面上“已加载”与“总数”不能混用。
- QueueEntry 继续以 EntryId 标识位置，歌曲 ID 标识内容；Source / SourceId 描述来源。FM 资格需要独立会话身份，不能仅凭可展示的 Source 字符串触发自动补取。

### 5.3 计划预算与失败降级

以下是本地实现的初始上限，不是对上游能力的断言。阶段 A 根据固定协议核对后可调整，但必须同步理由、测试边界和专用契约；不全局放大现有传输限制。

| 项目 | 初始约束 |
| --- | --- |
| HTTP | 继续使用现有 15 秒 / 1 MiB 请求边界；普通发现读取失败不后台循环重试；用户可明确刷新，限流遵守 Retry-After |
| 加载并发 | 仅加载当前可见内容；每 Document 最多 2 个发现读取，同一区块同一代次最多 1 个；作品子页按访问懒加载 |
| 列表 | 单页最多 50；可分页目录 / 歌手集合最多保留 1,000 个有效条目；已用歌单路径沿用每页 30、目录 1,000、曲目 ID 10,000 的边界 |
| 单次歌曲快照 | 推荐或专辑最多 1,000 首，仍受 1 MiB 限制；远端仅返回一批时不额外编造分页；不完整时只提供“播放 / 加入已加载歌曲” |
| 资料与图像 | 歌曲资料按现有批量上限 50、缓存上限 500 复用；图片使用现有可见性 / 租约和预算，不建立无界封面缓存 |
| 页面快照 | 每 Document 最多保留 8 个作品导航快照；普通推荐 / 榜单内存缓存建议 5 分钟；个人数据只在当前账号 Epoch 内复用，不新增磁盘缓存 |
| 每日推荐日期 | 服务端有可信日期时显示；没有时显示抓取时间。日期分桶 / 到期语义阶段 A 核对后冻结，不凭本机零点推测服务端刷新点 |
| 远端历史 | 最近记录和各排行范围分别最多保留 1,000 项；不支持翻页时显示“接口返回范围”，不得标为账号全部历史 |
| FM | 详见第 7 节：单会话单个在途读取，待播最多 10 首，近期去重窗口 100 个 ID；每轮最多 3 次 / 20 秒，失败候选总上限 20 |

刷新失败时，同账号旧快照可以带“未刷新成功 / 抓取时间”保留；换账号必须立即清除。空成功显示空态，协议错误显示错误，不能统一变成“暂无推荐”。通用推荐有独立来源标签；个性推荐失败只提示用户切到通用推荐，不把通用内容贴上“每日推荐”。

## 6. 页面、普通播放与远端历史

### 6.1 页面入口和导航

主导航增加“发现”，初次打开不改变现有默认搜索页。发现页提供每日推荐、推荐歌单、榜单和私人 FM 的明确入口；歌手 / 专辑为页内作品导航，返回保留来源列表、筛选和滚动位置。最近播放仍通过已有历史入口访问，在内部切换“本地最近”“网易最近”“网易听歌排行”。

每个区块独立 Loading / Ready / Empty / Failed 状态，局部失败不盖住整个播放器。切页或刷新取消前一请求；提交结果同时验证会话 Epoch 和导航请求代次。进作品页不关闭歌词 / 队列抽屉，不启动或替换播放。

歌曲行、播放条和作品菜单复用既有控件与库操作。多歌手采用轻量选择菜单；标题文本仍可阅读。歌单收藏沿用 V7 可信状态、令牌和写后回查，不由推荐卡片自行翻转收藏图标。

### 6.2 队列规则

- 单曲立即播放使用现有 `PlayNowAsync`；下一首 / 追加使用 `EnqueueAsync`，反馈依据实际接纳数。浏览 / 刷新 / 收藏 / 打开作品页不触发媒体打开。
- 完整推荐快照或完整专辑可以“播放全部”；歌手分页和不完整响应只能“播放已加载”，附实际数量，不为按钮后台遍历整位歌手的所有作品。
- 榜单和推荐歌单复用现有完整 ID 快照策略，不能用目录中三首摘要或当前 50 行代替整单。歌曲资料缺失仍保留有效身份；是否可播由原资源解析决定，不根据推荐身份保证权限。
- 加入队列遵循原本允许重复歌曲的规则。目录去重、FM 防重复和队列条目身份是三种不同语义，不能用全局按歌曲去重破坏用户主动重复入队。
- 所有提交捕获来源、目标 ID 与代次；载入作品期间切账号 / 切页，旧结果不得播放或覆盖新选择。

### 6.3 远端记录语义

本地最近继续由现有真实播放推进规则写入；读取网易记录不向本地历史灌入条目，也不替换本地恢复队列。网易最近的服务端时间有值且单位已核对时才展示，未知时间不拿抓取时间冒充。

`user_record` 用“网易听歌排行”表示；周 / 全部等实际支持范围在端点核对后映射，不将排行当时间顺序的最近播放。分值、排名、次数分别表达，没有次数依据就不标“播放 N 次”。范围切换重新建立代次，失败保留本地历史可用。

新播放不承诺立刻进入远端记录；V8 不发送播放上报。页面应简短说明“网易返回的记录可能延迟，与本机记录范围不同”。

## 7. 私人 FM 专项设计

### 7.1 与普通队列的关系

FM 是临时内容来源会话，不是新增第五种 `PlaybackMode`。仍只有一个播放器和一个可观察队列。用户在 FM 入口显式点击“开始私人 FM”，界面说明将替换当前待播队列；首次取到可接纳内容后，队列在同一原子入口核验账号、FM SessionId 和预期 QueueRevision，再提交切换。取不到内容或期间用户改队列时保持原队列，旧 FM 启动不能覆盖新意图。

进入 FM 时暂存普通模式，FM 期间按供应顺序播放，禁用循环 / 随机选择及“上一首”；本阶段不实现 FM 历史回访，退出后恢复普通模式与原导航能力。队列改动、普通单曲点播 / 播放全部、明确切回普通模式、清空或停止都会先退出 FM，再按原普通意图执行。只浏览 / 收藏 / 喜欢或打开抽屉不退出 FM。

结束 FM 不重建进入前的旧队列；保留当前及已接纳曲目为普通队列并恢复模式，用户显式 Stop 则同时停止。FM 队列显示为服务管理：不提供 FM 会话内的拖动 / 移除 / 撤销；用户从外部追加 / 插入歌曲时先退出 FM，再执行该操作。不要留一个隐蔽的普通队列与 FM 队列轮流覆盖。

普通恢复仍静默。FM 的运行资格、补取任务和反馈资格不持久化；可沿用现有队列白名单保存已接纳曲目，重开 / 重启按普通暂停队列处理并恢复普通模式，Source 文案不能使 FM 自动复活。

### 7.2 单一推进者与有限补取

FM 服务维护 `Idle / Loading / Active / WaitingForContent / Exhausted / Failed` 等少量内容状态，播放 / 暂停仍以现有播放事实为准。网络在队列锁外完成，结果入队由唯一队列写入者完成；FM 不直接响应原生 Ended 再调用 Next，防止与既有 AttemptId 终态处理双重推进。

| 触发 | 计划行为 |
| --- | --- |
| 首次开始 | 明确用户意图后取首批；成功且身份仍有效才原子切换队列和播放 |
| 待播少于 2 首 | 仅 Active 且正在播放时允许一轮预取；已有请求则共用该轮，不创建第二条补取链 |
| 自然结束 / 手动下一首 | 同一队列入口接纳一次推进；有待播即消费，没有则等待已有补取或启动一轮；暂停时换待播项保持暂停 |
| 暂停 | 不启动新预取；已在途结果可在身份有效且容量允许时入缓冲，不自动出声；用户明确下一首可进行一次有界取数 |
| Stop / Clear / 退出 FM / 账号撤销 / 最后页关闭 | 同步撤销接纳资格并取消补取；迟到结果不得入队、重启或出声 |
| 重新打开页面 | 只订阅已有共享事实；FM 已结束时必须再次显式开始，不自动请求 |

每轮包含首次请求在内最多 3 次，第二 / 三次前分别等待 500 / 1,500 ms，总窗口最多 20 秒；每个请求受单请求限制和剩余总预算共同约束。仅空批或整批重复允许在该轮补取；网络、协议、限流、验证要求、账号失效即停止该轮，不高速重试。等待和请求均可取消并使用可控时钟测试。

单账号 FM 同时最多一个内容请求；缓冲最多 10 首，批次截断有记录；与当前 / 待播及最近 100 个 FM 歌曲 ID 去重。历史已消费 FM 条目也有上限，保留最近最多 100 条（含当前），不让队列随收听时间无界增长；淘汰由队列协调器执行，不移除当前项。

既有“内容不可用最多寻找 20 个不同候选”必须覆盖 FM 自动补取的整个连续失败链，不能每次请求 / 新批次清零；只有真实进入正常播放或用户开始新的明确尝试才重置。网络 / 设备 / 协议错误停止自动推进。空 / 重复耗尽后置 Exhausted，等待用户明确重试，不在每个进度回调重启补取。

### 7.3 下一首与“不喜欢”的远端写入

“下一首”只影响本地播放，`fm_trash` 调用数必须为 0。“不喜欢这首”是独立按钮 / 菜单，明确说明会影响网易私人 FM 推荐，不附带取消歌曲喜欢。

反馈意图在接纳时绑定 AccountId、Epoch、FmSessionId、EntryId、TrackId 和本次操作身份。应用层确认它仍属于当前 FM 条目；两页重复点击共用写入资格，同一目标在本 FM 会话内最多发送一次，其余显示忙碌 / 已反馈。FM 写请求不排队等待以后自动发送，不自动重试。

| 结果 | 页面与播放行为 |
| --- | --- |
| 发送前取消 / 校验失败 | 标明未发送，无远端成功提示，无自动换曲 |
| 有明确成功回执 | 标明已反馈；仅当仍是同一 FM 当前条目且未被 Next / 自然结束处理时推进一次；暂停状态仍暂停 |
| 明确拒绝 | 提示原因，保留当前曲；用户可选择普通下一首 |
| 超时、发送后取消、损坏回执等无法确认 | 显示“结果未确认，未自动重发”；不自动换曲或提供一键重发；用户仍可普通下一首 |

若固定接口没有可信的反馈状态查询，**不得承诺可写后回查确认**，下一批不再出现该歌曲也不是远端成功证据。成功回执后凭据保存失败要分别保留回执事实与存储错误，不能因此再发一次写请求。账号撤销后旧操作可能已在服务端生效，但不能提交到新账号 UI。

## 8. 并发、寿命与详细中文注释

所有个人快照以 AccountId + Epoch 隔离，CredentialVersion 继续由现有受控提交路径管理。读取完成后、UI 调度落地前、入队前和写回执应用前分别校验适用身份；只在请求开始检查一次不足以保护排队中的 UI 回调。

Document 关闭释放本页读取、订阅和图像租约；非最后页不停止其他页共享 FM。最后页关闭、退出账号或插件 Shutdown 先撤销 FM 资格，再取消并有界等待任务，接续既有播放保存 / 释放顺序。重复 Dispose 等待同一尾任务，不能在 UI 线程同步等待依赖 UI 的 continuation。旧任务 `finally` 只能释放自己持有的忙碌资格。

新增接口、结果、关键状态和并发方法均写中文 XML / 行注释，至少说明：

- 为什么按该职责拆分，谁拥有状态，哪个调用点是原子接纳边界。
- 空结果、失败、不完整和结果未知的区别；排序 / 去重为何不共用一个规则。
- Epoch、导航代次、QueueRevision、EntryId、AttemptId、FmSessionId 各自防止哪类陈旧操作。
- 取消只能停止等待 / 未发送工作，不能撤销已经发出的远端写入。
- FM 补取预算、停止条件、暂停 / 关闭行为及旧任务清理的设计原因。
- 旧持久化资料缺作品身份时为何延迟补全，以及远端历史为什么不写本地历史。

示例仅说明注释标准，以下端口与类型尚未实现：

```csharp
/// <summary>
/// 对当前私人 FM 条目提交一次“不喜欢”反馈。
/// 设计思路：反馈资格由共享 FM 会话持有，两个页面不能各自重发同一目标。
/// 目标包含会话和条目身份，避免网络返回时把旧曲反馈应用到刚切换的新曲。
/// 发送后超时只能说明结果未知；没有可信查询接口时不能用下一批歌曲推断成功。
/// </summary>
/// <param name="target">接纳时捕获的账号、FM 会话及歌曲条目身份。</param>
/// <param name="ct">取消尚未发送的操作或等待，不表示撤销服务端已收到的反馈。</param>
/// <returns>未发送、成功回执、明确拒绝或结果未知；不把未知折叠成普通失败。</returns>
Task<FmFeedbackResult> DislikeAsync(FmFeedbackTarget target, CancellationToken ct);
```

注释必须与真实代码一致，不能以注释宣称“线程安全 / 自动释放”代替断言。关键测试及门禁脚本也使用中文说明其针对的风险和失败依据。
